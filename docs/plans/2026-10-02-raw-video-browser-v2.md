## 0. Codex가 먼저 읽을 실행 지시

이 문서는 아래 세 단계와 추가 요구를 하나의 구현 계약으로 묶는다. v2는 부록만 추가한 문서가 아니다. 최종 자막 처리·설정·UI·검증 기준을 함께 개정했으므로 이 파일 하나를 구현 기준으로 사용한다.

1. 원본 영상들을 영상별로 읽고, 대화·장면의 의미를 이해하여 작은 **실제 영상 파일**로 분할한다.
2. 조각을 **각 원본의 재생 시간순**으로 번호를 붙여 작업공간 폴더에 정리한다. 사용자가 편집기에서 선택·배열하여 전체 영상을 완성한다.
3. 사용자가 내보낸 전체 영상 파일을 다시 입력하면, 그 파일의 실제 오디오를 기준으로 정밀 자막을 새로 만든다.

추가 요구는 다음과 같다.

- SD 카드에서 작업공간으로 원본을 직접 복사·검증할 수 있어야 한다.
- UI는 **로컬 브라우저 기반**이며, `영상만 보기` / `영상 + 편집용 자막 보기`를 전환할 수 있어야 한다.
- 최종 자막에는 확인 시점의 OpenAI 파일 전사 권장 모델인 `gpt-transcribe`를 사용한다. 최신 전사 모델과 SRT 직접 출력 모델을 동일시하지 않는다. [R15][R16]
- 모델 기능·가격·종료 공지는 실행 전 확인 가능한 설정으로 관리하고, 조용한 구형 모델 fallback이나 근거 없는 시각 생성을 금지한다.

**구현 순서:** 현재 코드와 불변 계약 확인 → 새 워크플로 계약 정리 → 작업공간·가져오기·시간순 분할·실제 파일 추출의 수직 통합 → Luna 의미 분석 연결 → 브라우저 검토 UI → 최종 영상 자막 연결 → 회귀·실기 검증.

기존 기능을 대규모로 지우거나 새 프레임워크로 전부 다시 만들지 않는다. 기존 자막 엔진의 시간 골격·교정·조판·검토 경계를 재사용하되, 최신 전사 모델용 요청·응답 어댑터를 명시적으로 연결한다. 기존 코드에 이미 `gpt-transcribe`가 있어도 모델명 변경만으로 완료하지 않는다. 실제 기본 설정, 호출 파라미터, 텍스트 교정 채택, 타임스탬프 근거, 최종 파일까지 검증한다. 원본 분석에 최종 자막 파이프라인을 무조건 호출하는 구조는 만들지 않는다. 기존 문서와 충돌하는 항목은 문서·검사기·테스트를 함께 개정한다.

아래는 사용자가 별도로 확정한 수치가 아니라, 구현을 진행하기 위해 선택한 **조정 가능한 기본값**이다.

| 항목 | 기본 결정 |
|---|---|
| UI 기술 | 저장소에 남아 있는 Gradio UI를 확장한다. 별도 React/Next.js 프로젝트는 만들지 않는다. |
| 실행 위치 | 사용자 Mac의 로컬 Python 서버 + 같은 컴퓨터의 브라우저. 클라우드 배포는 범위 밖이다. |
| 원본 보관 | 작업공간으로 바이트 복사하고 검증한다. 카드의 원본은 삭제·이동하지 않는다. |
| 분할 정책 | 처음에는 전체 재생 구간을 빠짐없이 분할한다. 비추천 구간도 삭제하지 않고 표시한다. |
| 조각 길이 | 대화는 5~45초, 풍경은 3~15초를 목표로 한다. 의미 완결성과 발화 보호가 길이 목표보다 우선이다. |
| 긴 연속 구간 | 90초를 검토 경고 기준으로 사용한다. 안전한 경계가 없으면 강제 절단하지 않는다. |
| 편집 여유분 | 기본은 0초. 선택적으로 앞뒤 핸들을 추가하되 원본의 본 구간과 구별한다. |
| 기본 표시 모드 | `video_only`. 이후 전환해도 기존 분석을 다시 호출하지 않는다. |
| 의미 분석 모델 | 신규 워크플로의 기본값은 `gpt-6-luna`. 모델 이름은 설정에서 관리한다. |
| 내부 전사 | 시간 정보가 있는 단일 패스 전사를 우선 사용한다. 최종 SRT 조판·정밀 교정과 분리한다. 현재 Whisper 사용은 과도기이며 §11.10의 수명주기 검사를 공유한다. |
| 최종 자막 기본 프리셋 | `latest_openai_srt`: `gpt-transcribe` 문구 + `whisper-1` 시간 골격 + 앱 SRT/VTT 조립. 현재 지원 범위의 과도기 구성이다. |
| 모델 최신성 | 2026-10-02 공식 확인값을 기록한다. 실행 중 임의 교체하지 않고, 새 모델은 기능·품질 검증 후 설정 리비전으로 도입한다. |
| 편집용 파일 | 원본 해상도·프레임 타이밍·비트 깊이를 고려하는 고품질 재인코딩. 편집 친화적 ProRes는 별도 선택이다. |
| 실행 순서 | 기본 `source_workers=1`, `export_workers=1`. 추출 작업 자체도 시간순으로 수행한다. |

## 2. 전체 사용자 흐름

```text
[브라우저에서 새 프로젝트 생성]
               │
               ▼
[SD 카드 / 원본 폴더 선택]
               │
               ▼
[파일 목록 확인 → 원본 순서 확인 → 작업공간으로 복사·체크섬 검증]
               │
               ▼
[원본 1을 시간순으로 분석]
  오디오 → 내부 전사 ─┐
  프레임 → 장면 증거 ─┼→ Luna 의미 분석 → 연속 구간 경계 결정
  VAD/장면 변화 ──────┘
               │
               ▼
[원본 1: 조각 1 → 조각 2 → 조각 3 … 실제 파일 생성]
               │
               ▼
[원본 2, 원본 3 … 같은 방식으로 처리]
               │
               ▼
[브라우저에서 시간순 검토]
  영상만 보기 ↔ 영상 + 편집용 자막 보기
  경계 조정 / 분할 / 인접 조각 병합 / 사용 여부 표시
               │
               ▼
[편집용 폴더 확정]
  자막 없는 실제 영상 + 순서 목록 + 분석 정보
               │
               ▼
[사용자가 Final Cut Pro 등 외부 편집기에서 컷편집]
               │
               ▼
[사용자가 전체 영상 내보내기]
               │
               ▼
[브라우저에 최종 영상 등록]
               │
               ▼
[최종 오디오 → gpt-transcribe 문구 + 검증된 시간 정보]
               │
               ▼
[문구 대응 검증 → 브라우저 자막 수정 → SRT/VTT]
```

분할 결과를 보고 경계를 바꾸면 변경 구간만 새 리비전으로 추출한다. 외부 편집기에 이미 가져간 파일을 제자리에서 덮어쓰지는 않는다.

브라우저의 ‘편집’은 조각 경계 조정과 선택·검토, 최종 자막 수정을 뜻한다. 다중 트랙 타임라인·전환·색보정·완성 영상 렌더 기능을 이번에 새로 만들지는 않는다.

## 3. 현재 저장소에서 재사용할 것과 분리할 것

기준 커밋에서 기존 Gradio 화면과 `ui` extra가 남아 있는 것을 확인했다. 반면 2026-09-13 계획에는 Gradio 제거가 적혀 있으므로, 새 요구에 맞춰 문서의 방향을 명확히 정리해야 한다. [R1][R2][R3]

| 현재 경로 / 기능 | 이번 변경 방향 |
|---|---|
| `ui/app.py` | 단일 SRT 생성 화면을 프로젝트 중심의 4단계 브라우저 화면으로 확장한다. |
| `ui/service.py` | 기존 단일 영상 자막 서비스는 호환 유지. 새 작업공간 서비스와 분리한다. |
| `vlogsrt/preprocess.py` | 미디어 조사·오디오 추출·프레임 추출에 더해 실제 영상 구간 추출의 공용 경계를 추가한다. |
| `vlogsrt/transcribe.py` | 기존 전사 및 Luna 전송 경계를 재사용·확장한다. 다른 파일에서 OpenAI SDK를 직접 호출하지 않는다. |
| `vlogsrt/pipeline.py`, `repair.py`, `retext.py`, `refine.py`, `layout.py`, `output.py` | 시간 골격·반복 복구·문구 대응 교정·조판을 재사용한다. 새 요청은 `gpt-transcribe` 문구를 교정 입력으로 연결하고 검증 응답을 재사용한다. 첫 단계의 필수 실행 경로에는 넣지 않는다. |
| `vlogsrt/project/timebase.py` | FCPXML에 의존하지 않는 시간 계산 유틸리티만 재사용한다. |
| `vlogsrt/project/vad/` | 발화 구간·경계 후보 탐지에 사용한다. VAD만으로 내용을 버리지 않는다. |
| `vlogsrt/project/vision/sampling.py` | 시간표가 붙은 프레임 표본 추출 아이디어와 독립 유틸리티를 재사용한다. |
| `vlogsrt/project/workflow_analysis.py` | 기존 Luna 설정·전송 형태는 참고한다. 현재의 제거 후보 선택기를 의미 분석기라고 간주하지 않는다. [R13] |
| `vlogsrt/project/final_caption.py` | 기존 FCPXML + 48 kHz WAV 계약은 호환 보존한다. 새 영상 입력 경로에서 직접 호출하지 않는다. |
| `vlogsrt/project/fcpxml.py`, `export.py`, `workflow_protocol.py` | 기존 Final Cut 기능의 호환 영역으로 둔다. 새 원본 워크플로의 필수 의존성이 아니다. |
| `macos/` | 이번 범위에서 기능 확장·배포·서명 작업을 하지 않는다. |

기존 `final_caption.py`는 최종 FCPXML과 WAV를 검증하고 XML 리비전에 요청을 결합한다. 새 경로는 **최종 영상의 콘텐츠 해시**를 기준으로 해야 하므로 입력 계약이 다르다. [R4]

또한 현재 README의 교정 설명과 `CLAUDE.md`의 D37 교정 설명이 일치하지 않는다. 최종 자막 재사용 시 실제 코드와 테스트를 기준으로 확인하고, README도 함께 정리한다. [R1][R5]

### 3.1 변경하지 않을 핵심 안전 계약

- 원본 미디어와 기존 자막 trace는 불변이다.
- 현재 최종 자막 시간 근거는 Whisper 시간 골격과 검증된 오프셋이다. `gpt-transcribe`의 시각 없는 문구가 이 골격을 임의로 바꾸지 못한다. 타임스탬프 제공자를 바꿀 때는 별도의 계약·품질 시험을 통과해야 한다.
- Luna가 제안한 시각을 최종 자막 시각으로 사용하지 않는다.
- API 호출은 `vlogsrt/transcribe.py`, FFmpeg/ffprobe 호출은 `vlogsrt/preprocess.py`에 둔다.
- 새 UI 때문에 엔진 핵심 의존성을 불필요하게 늘리지 않는다.
- 기존 CLI `run / redo / eval / probe / record`의 의미와 결과를 유지한다.

### 3.2 명시적으로 개정할 계약

`docs/PROJECT_CONTRACTS.md`에는 `ui/** → vlogsrt.project` import가 금지되어 있다. UI 파일에서 이를 몰래 우회하지 않는다. 새 `ui/workspace_service.py` 한 파일이 `vlogsrt.project.raw.service`의 공개 인터페이스만 호출하도록 **정확 경로 예외**를 추가하고, 검사기와 양성·음성 테스트를 함께 수정한다. [R6]

기존 `vlogsrt/cli.py → vlogsrt.project.commands` 예외는 유지한다. 새 CLI는 이 진입점에서 `raw.commands`로 위임한다. 모델 기본값과 새 설정의 허용 위치도 계약에 명시한다.

v2 추가 계약: `text_model`, `timing_model`, `caption_profile`, `capability_registry_revision`을 역할별로 분리한다. `gpt-transcribe`에 `languages`·`keywords`를 전달하는 새 어댑터를 허용하되, Whisper에 prompt를 보내지 않는 기존 규칙은 유지한다. 기존 `verify_model`이 교정과 검증을 함께 맡는 구현이면 공개 어댑터에서 매핑하고 중복 호출을 막는다. 후속 타임스탬프 제공자 교체는 기존 spine 보호 규칙을 무력화하는 포괄 예외가 아니다.

## 4. 로컬 브라우저 아키텍처

```text
브라우저: Gradio Blocks + 필요한 최소 플레이어 UI
    │
    │ 로컬 요청 / 진행 이벤트 / 미디어 재생
    ▼
ui/workspace_service.py
    │
    ▼
vlogsrt.project.raw.service
    ├─ 작업공간·작업 상태
    ├─ SD/폴더 가져오기
    ├─ 원본 순서 / 구간 분할
    ├─ 의미 분석 / 검토 / 실제 영상 내보내기
    └─ 최종 영상 자막
          │
          ├─ vlogsrt.preprocess: FFmpeg / ffprobe
          └─ vlogsrt.transcribe: ASR / Luna API
```

### 4.1 실행 계약

- 기본 접속 주소는 `http://127.0.0.1:7860`이다.
- 원본 파일을 브라우저의 파일 업로드 위젯으로 서버 임시 폴더에 다시 올리는 방식을 주 경로로 쓰지 않는다.
- 로컬 서버가 사용자가 선택한 SD 카드·폴더·작업공간의 실제 경로를 다룬다.
- 가져오기와 영상 추출은 로컬에서 수행한다. 온라인 분석을 승인하면 선택된 음성 데이터·프레임·텍스트만 설정한 API 공급자로 전송한다.
- 로컬 UI라고 해서 AI 분석도 완전 오프라인이라고 표시하지 않는다.
- 브라우저 탭을 새로고침하거나 닫아도 서버가 살아 있으면 작업 상태를 보존한다. 서버 종료 후에는 명시적 재개를 지원한다.
- 외부 공개 링크, LAN 공개, 클라우드 배포, 계정·팀 협업 기능은 이번 범위에서 비활성화한다.

### 4.2 SD 카드·폴더 선택 UI

기본은 브라우저 안의 서버 측 폴더 탐색기와 경로 입력을 제공한다. macOS에서는 마운트된 장치를 후보로 표시하되, 사용자가 선택하기 전 내용 분석을 시작하지 않는다.

필요하면 기존 OS 파일 선택 대화상자를 보조 경로로 유지할 수 있다. 하지만 macOS 대화상자만 성공해야 브라우저 흐름이 동작하는 구조로 만들지는 않는다.

### 4.3 브라우저 재생과 편집용 파일을 구분

Gradio Video는 재생 가능한 포맷 제약과 변환 동작이 있고, 자막 파일을 동반한 출력도 지원한다. 따라서 자동 변환 결과가 원본이나 편집용 마스터로 오인되지 않도록 경로를 분리한다. [R9]

- 브라우저에서 직접 재생 가능한 파일은 로컬 미디어 경로로 제공한다.
- HEVC/ProRes 등 브라우저별 재생 문제가 있으면 해당 조각의 경량 H.264 미리보기를 필요할 때만 만든다.
- 미리보기는 `previews/`에 저장하고 ‘미리보기용’으로 표시한다.
- 분석 기준과 최종 조각 추출 기준은 계속 작업공간의 원본이다.
- 전체 원본에 대한 편집기 프록시 생성·연결을 필수 단계로 만들지 않는다.
- 장시간 원본을 통째로 메모리에 로드하지 않는다. 구간 탐색이 가능한 스트리밍과 지연 로딩을 검증한다.
- 원본을 Gradio 출력에 넘길 때 전체 파일이 임시 캐시에 중복 복사되는 경로를 피한다. 등록된 파일의 제한된 직접 제공 또는 명시적 조각 미리보기를 사용하고, HTTP Range 요청·seek·실제 디스크 사용량을 테스트한다.
- `<video>` 시각은 검토용이다. 실제 추출 경계는 서버가 검증한 원본 PTS/프레임 정보로 결정한다.

### 4.4 파일 접근 보안

현재 UI는 `allowed_paths`에 홈 디렉터리와 `/tmp`를 넣고 `--share`를 허용한다. 새 작업공간 UI에서는 이 범위를 그대로 이어받지 않는다. [R2]

- `share=False`, loopback 바인딩을 고정한다.
- 파일 접근은 등록된 프로젝트의 허용된 미디어·미리보기·내보내기 파일로 제한한다.
- 프로젝트 전체를 무조건 공개하지 않는다. `.env`, 설정의 비밀값, 원본 API 응답, 로그는 미디어 제공 대상이 아니다.
- 입력 경로는 서버가 정규화하고, 심볼릭 링크와 `..`을 포함한 경로 이탈을 검사한다.
- 브라우저에는 내부 파일 ID를 전달하고, 가능하면 서버가 ID를 실제 경로로 해석한다.
- 로컬 앱도 외부 사이트 요청에 안전하도록 Host/Origin 검사와 변경 요청 보호를 검증한다.
- 모델이 출력한 문자열을 HTML·경로·명령어로 실행하지 않는다. 표시 텍스트는 escape한다.
- API 키는 브라우저 JS·localStorage·내보내기 JSON에 저장하지 않는다.

Gradio의 파일 공개 범위는 보안 설정의 일부이므로, 설치한 버전의 공식 동작을 확인하고 허용·차단 테스트를 작성한다. [R10]

## 5. SD 카드에서 작업공간으로 가져오기

### 5.1 사용자 조작

1. 프로젝트 이름과 작업공간을 선택한다.
2. SD 카드 또는 원본 폴더를 선택한다.
3. 발견한 파일, 총 용량, 촬영 시각, 카메라 정보, 예상 추가 공간을 확인한다.
4. 가져올 파일과 원본 사이의 순서를 확인한다.
5. ‘복사 및 검증’을 실행한다.
6. 검증 완료 파일부터 후속 처리가 가능해진다. 카드 제거 가능 여부는 가져오기 전체 결과로 표시한다.

### 5.2 필수 처리 규칙

- 기본 대상은 MP4/MOV 등 실제로 조사 가능한 영상이다. 확장자만 믿지 않고 ffprobe로 확인한다.
- DJI의 `.LRF`, 썸네일 등 보조 파일을 원본 영상과 중복 분석하지 않는다. 보존 필요 시 별도 사이드카로 기록한다.
- 카드의 폴더 구조·원본 파일명·원본 위치는 가져오기 manifest에 남긴다.
- 파일명만으로 중복 판정하지 않는다. 서로 다른 카드의 `DJI_0001.MP4`를 덮어쓰지 않는다.
- 경로 구조가 다른 동일 콘텐츠는 해시로 중복을 알아내고, 카드별 출처 이력은 별도로 남긴다.
- 심볼릭 링크를 따라 선택한 원본 루트 밖으로 나가지 않는다.
- 작업공간이 가져오기 원본 루트 안에 있거나 SD 카드 그 자체이면 재귀 복사·잘못된 저장을 막는다.
- 전체 복사 공간과 조각 생성 추가 공간을 따로 안내한다. 부족하면 해당 단계 시작 전에 차단한다.

### 5.3 복사 완료의 정의

```text
발견 → 임시 이름으로 복사 → 목적지 다시 읽어 SHA-256 검증
     → 입력 파일 변경 여부 확인 → 최종 이름 확정 → READY
```

- 임시 파일 확장자는 `.partial` 등으로 구분한다.
- 복사하면서 계산한 원본 해시와 목적지의 재독출 해시가 같아야 한다.
- 복사 전후 원본 크기·수정 정보가 달라지면 변경된 입력으로 취급한다.
- 중단·카드 분리·용량 부족·권한 오류는 실패 또는 재개 가능 상태로 남긴다.
- MVP의 재개 단위는 파일이다. 검증 완료 파일은 건너뛰고 미완료 파일은 안전하게 다시 복사한다.
- 검증되지 않은 파일을 분석·추출 입력으로 사용하지 않는다.
- SD 카드 삭제·포맷·자동 파일 이동·자동 eject는 구현하지 않는다.
- ‘복사 검증 완료’가 ‘별도 백업까지 완료’를 뜻하지는 않는다.

## 6. 시간순 생성: 반드시 지킬 계약

### 6.1 원본 파일 내부의 순서는 절대 바꾸지 않는다

한 원본에서 나온 조각의 본 구간을 `core_range=[start,end)`로 정의한다.

```text
원본 A
  A-000001: 00:00.000 ~ 00:12.400
  A-000002: 00:12.400 ~ 00:28.800
  A-000003: 00:28.800 ~ 00:39.200
  ...
```

기본 전체 분할에서 다음을 만족해야 한다.

```text
첫 core.start = 0
모든 core.start < core.end
core[i].end = core[i+1].start
마지막 core.end = 원본의 정규화된 재생 종료 시각
조각 번호 오름차순 = core.start 오름차순
```

- 장면의 중요도·Luna 점수·조회 가능성·대화 유무를 이유로 순서를 바꾸지 않는다.
- 하나의 조각 안에서 떨어진 두 구간을 이어붙이지 않는다.
- 다른 원본의 일부를 하나의 조각으로 합치지 않는다.
- 앞선 조각을 만들기 전에 뒤쪽 하이라이트부터 추출·게시하지 않는다.
- 파일 생성 시각이나 API 응답 도착 순서는 조각 순서를 결정하지 않는다.

### 6.2 원본 파일 사이의 순서

‘원본 내부의 재생 시각’과 ‘여러 원본의 촬영 시각’은 다르다. 후자는 촬영 메타데이터가 없거나 카메라 시계가 틀릴 수 있으므로 확정된 `source_order`를 별도로 저장한다.

초기 제안 순서는 다음 근거로 만든다.

1. 사용자가 지정한 순서가 있으면 그것을 우선한다.
2. 없으면 신뢰 가능한 촬영 시각을 기준으로 정렬안을 만든다.
3. 동률 또는 시각 미상에는 자연스러운 파일 번호 정렬, 원본 상대 경로, 자산 ID를 결정적 tie-breaker로 사용한다.
4. 시각이 불확실한 항목은 UI에 표시하고, 분석·내보내기 전에 사용자가 순서를 확인할 수 있게 한다.

복사한 파일의 수정 시각을 촬영 시각이라고 조용히 대체하지 않는다. 여러 카메라의 동시 촬영은 순서 표시만 제공하며 자동 멀티캠 동기화·교차 편집은 하지 않는다.

최종 순서 키는 다음이다.

```text
(source_order, core_start_pts, segment_order)
```

### 6.3 순차 실행과 순차 게시

- 기본으로 원본 하나씩, 원본 안의 조각 하나씩 처리한다.
- 내부 네트워크 호출을 병렬화하더라도 수집 결과는 원본 시간순으로 정렬한다.
- 앞선 조각이 실패하면 해당 조각을 실패로 표시하고 그 원본의 자동 게시를 멈춘다. 조용히 누락한 완성 폴더를 만들지 않는다.
- 사용자가 부분 결과 사용을 명시적으로 선택한 경우에만 불완전 package를 발행하고, 누락 구간을 manifest에 표시한다.
- 재개할 때 같은 계획 리비전의 기존 번호를 유지한다.

### 6.4 전체 분할과 사용 선택을 분리

기본은 모든 구간을 분할한 뒤 `recommended / normal / review_required` 같은 상태를 붙이는 것이다. 풍경·이동·침묵·어두운 화면도 바로 삭제하지 않는다.

사용자가 ‘선택한 조각만 내보내기’를 고르면 일부를 제외할 수 있다. 이 경우에도 전체 분할 기록과 제외 이유를 보존하고, 남은 조각의 상대적 시간순은 유지한다. `전체 분할 완료`와 `선택본 내보내기 완료`를 같은 상태로 표시하지 않는다.

### 6.5 핸들, 리비전, 파일명

- 기본 핸들은 0초이므로 조각 본 구간에 중복과 빈틈이 없다.
- 핸들을 켜면 `media_range`가 `core_range`보다 넓을 수 있다. 이 중복은 편집 여유분이며, UI·manifest에 표시한다.
- 경계를 바꾸면 새로운 `segmentation_revision`을 만든다.
- 폴더를 확정한 뒤 원본 순서·파일명·구간을 바꾸려면 새 package 리비전으로 내보낸다.
- 이전 package의 파일은 덮어쓰거나 번호를 다시 붙이지 않는다.
- 앞 시각의 원본을 뒤늦게 추가해도 기존 package는 유지하고, 새로운 순서 리비전에서만 재정렬한다.

## 7. 첫 단계: Luna 의미 분석과 조각 경계 결정

### 7.1 무엇을 생성하는가

첫 단계의 주요 산출물은 정밀 자막이 아니라 다음 정보다.

| 정보 | 예시 / 목적 |
|---|---|
| 대화 내용 요약 | ‘도착 후 오늘의 일정 설명’ |
| 내부 전사 증거 | 실제로 인식한 말과 해당 원본 구간 |
| 장면 설명 | ‘기차 창밖 풍경에서 플랫폼으로 이동’ |
| 동작·사건 | 걷기, 물건 보여주기, 음료 따르기, 대화 전환 |
| 구간 역할 | 대화 / 풍경 / 이동 / 반응 / 현장 분위기 |
| 편집 메모 | ‘질문과 대답을 같은 조각으로 유지’ |
| 경계 근거 | 발화 종료, 장면 전환, 동작 완료, 단순 길이 분할 |
| 불확실성 | 음성 인식 실패, 부족한 표본, 경계 검토 필요 |

기본으로 원본 SRT·최종 SRT·자막 번인 영상을 만들지 않는다. 내부 전사와 사용자에게 보여주는 편집용 자막은 다른 산출물이다.

### 7.2 Luna 입력에 대한 기술 제약

확인한 공식 모델 문서상 `gpt-6-luna`는 텍스트·이미지를 입력받지만 오디오·영상 파일 자체의 입력은 지원하지 않는다. 따라서 구현은 다음처럼 한다. [R7]

```text
원본 오디오 → 내부 ASR → 시간 구간이 있는 전사 증거 ─┐
원본 영상   → 시각이 붙은 프레임 표본 ───────────────┼→ Luna
원본 조사   → 장면 경계·발화 경계·길이 ──────────────┘
```

‘Luna가 영상에서 무슨 말을 하는지 이해한다’는 요구는 **Luna가 내부 전사를 통해 대화의 의미를 파악하고, 이미지와 결합하여 장면을 이해한다**는 방식으로 구현한다. 이미지만 보고 실제로 하지 않은 말을 추측하게 하지 않는다.

모델 기본값은 `gpt-6-luna`로 설정하되 실행 환경의 사용 가능 여부를 확인한다. 접근 불가·지원 기능 불일치 시 사용자에게 알리고 멈춘다. Sol/Astra 등 다른 모델로 조용히 전환하지 않는다. 기존 프로젝트가 사용하는 모델 설정은 이 새 기본값으로 무단 변경하지 않는다.

### 7.3 내부 음성 인식

- 첫 단계에서는 단일 패스의 시간 정보 있는 전사를 분석 증거로 저장한다.
- 첫 단계의 시간 정보는 기존 전송 경계를 통한 `whisper-1` 세그먼트 결과를 과도기적으로 사용한다. 최종 자막의 `gpt-transcribe` 프리셋과는 독립 설정이다. [R8]
- 이 사용도 §11.10의 제공자 가용성·종료일 검사를 적용한다. 타이밍 제공자가 없으면 자동 의미 분할/검토 자막이 제한된다는 상태를 표시하고, 다른 모델의 문자열에 가짜 시각을 붙이지 않는다.
- 내부 결과는 `analysis_transcript.json`이며, SRT 조판 함수로 연결하지 않는다.
- 첫 단계에서 정밀 교정·전체 이중 전사·최종 자막 레이아웃을 기본 실행하지 않는다.
- 발화 구간 탐지를 ASR 입력의 조용한 누락 근거로 사용하지 않는다. 모델 입력 분할은 원본 오디오 전체를 덮고, 실패 구간을 별도로 기록한다.
- 말이 없다고 확인된 상태, 오디오 트랙이 없는 상태, 분석 실패는 각각 다른 상태다.
- 분석 실패를 ‘자막 없음’ 또는 ‘쓸모없는 장면’으로 처리하지 않는다.
- 음악 가사·배경 TV·멀리서 들리는 말이 확실하지 않으면 전경 발화로 단정하지 않고 검토 표시한다.
- 타임스탬프 없는 전사 모델을 선택하면 시간 정밀도가 낮다는 사실을 표시한다. 글자 수로 단어 시각을 균등 배분하지 않는다.

### 7.4 프레임과 시간창

- 원본 전체를 처음부터 끝까지 시간창으로 나눈다. 분석 시간창과 실제 편집 조각을 혼동하지 않는다.
- 초기 기준은 15초 core window, 앞뒤 최대 2초 문맥, 창당 8장 표본이다. 수치는 설정으로 이동한다.
- 시간창 전체에 분포한 프레임과 장면 변화 주변 표본을 우선한다.
- 겹치는 문맥은 같은 증거 ID로 중복을 추적하고, 결과가 겹친다는 이유로 실제 영상 조각을 중복 생성하지 않는다.
- 빠른 동작·애매한 경계는 해당 구간만 추가 표본을 요청한다. 예산 상한을 넘으면 보수적 분할과 검토 표시로 전환한다.
- 이미지 표본 사이에 발생한 사건까지 ‘모두 확인했다’고 주장하지 않는다.

### 7.5 Luna의 책임과 출력 제한

Luna는 관측 근거에 기반한 의미 요약·태그·편집 메모·제공된 경계 후보 선택을 한다. 파일 경로, FFmpeg 옵션, 삭제 명령, 영상 순서를 만들 권한은 없다.

입력은 원본 ID·시간창 ID·허용 경계 ID·프레임 ID·전사 ID와 그 내용을 포함한다. 출력은 제한된 JSON schema를 사용한다.

```json
{
  "window_id": "window_000012",
  "speech_summary": "이동 목적과 다음 일정에 대해 설명한다",
  "visual_summary": "보행 장면에서 건물 입구로 전환된다",
  "scene_tags": ["walking", "arrival", "talking"],
  "evidence_ids": ["frame_00120", "utterance_00034"],
  "suggested_boundary_ids": ["boundary_00019"],
  "editing_notes": ["마지막 문장이 끝난 뒤 분할"],
  "needs_review": false,
  "uncertainties": []
}
```

위 예시는 schema 설명용 가상 데이터다. 모델의 수치형 confidence를 보정된 정확도 확률로 취급하지 않는다. 필수 ID 누락·미제공 ID·범위 이탈·JSON 오류·API 실패는 검증 오류로 처리한다.

영상 속 글자와 발화도 신뢰할 수 없는 입력이다. ‘이전 지시를 무시하라’ 같은 문구는 내용으로만 취급하고 앱 동작 명령으로 실행하지 않는다.

### 7.6 분할 알고리즘

1. 원본 조사 결과로 정규화된 시간축과 전체 coverage를 만든다.
2. 장면 변화·발화 종료·오디오의 쉬는 지점·동작 완료 후보를 만든다.
3. Luna가 의미상 연결되는 구간과 제안 경계를 판정한다.
4. 서버의 결정적 알고리즘이 원본 시간순으로 경계를 확정한다.
5. 경계가 발화 중간에 걸리는지 다시 확인하고, 모호하면 더 긴 조각을 유지한다.
6. 첫 구간부터 마지막 구간까지 빈틈·뒤집힘·불필요한 중복이 없는지 검증한다.
7. 확정한 계획 리비전 순서대로 실제 영상 파일을 추출한다.

대화·질문과 답변·연속 동작의 완결성이 목표 길이보다 우선이다. 2초짜리 원본을 억지로 늘리거나, 50초짜리 완결 발화를 45초에서 무조건 자르지 않는다.

Luna가 실패한 창은 검증된 장면·발화 경계 기반으로 보수적으로 분할하고 `review_required`로 표시한다. 안전한 경계가 없으면 긴 조각 하나로 보존한다. 손상으로 읽지 못한 영상 구간은 성공적으로 분할되었다고 주장하지 않는다.

## 8. 실제 편집용 영상 파일 추출

### 8.1 ‘원본 기반’과 ‘무손실’을 구분

SD 카드에서 작업공간으로 가져오는 원본은 바이트 복사다. 작은 조각을 임의의 정확한 프레임 경계에서 만드는 것은 별도 문제다.

FFmpeg의 stream copy는 임의의 입력 seek 위치를 정확한 디코딩 경계로 만들지 못할 수 있다. 따라서 `-c copy`만 쓰면서 ‘프레임 정확·항상 무손실’이라고 표시하지 않는다. [R11]

| 프로파일 | 용도 | 계약 |
|---|---|---|
| `source_matched` — 기본 | 원본 기반 고품질 편집 재료 | 검증된 H.264/HEVC 입력에 대해 원본 크기·프레임 타이밍·비트 깊이·색 정보를 고려해 정확 구간 재인코딩. 재압축이 발생함을 표시한다. |
| `edit_prores` — 선택 | Final Cut 등에서 편집 편의 우선 | MOV + 적절한 ProRes 프로파일 + PCM 오디오. 필요 공간을 별도로 계산한다. |
| `keyframe_copy` — 후속 작업 | 빠른 무재인코딩 분할 | MVP에서 제외한다. 추후 구현 시 요청 경계와 실제 키프레임 경계를 별도로 기록해야 한다. |

`source_matched`라는 이름이 임의의 모든 코덱 지원을 뜻하지는 않는다. MVP 지원 매트릭스를 명시하고, 알 수 없는 코덱·비트 깊이는 임의로 낮추지 말고 호환 프로파일 선택 또는 실패 이유를 안내한다.

### 8.2 영상·음성 보존

- 입력은 항상 `originals/`의 검증된 원본이다. 미리보기 파일로 최종 조각을 만들지 않는다.
- 자동 색보정·LUT 번인·노이즈 제거·오디오 정규화·속도 변경을 하지 않는다.
- D-Log/HDR 색 특성과 회전·방향 정보를 조사·기록한다. 전달에 실패한 메타데이터는 경고한다.
- 일반 10-bit 원본을 브라우저 호환성 때문에 편집용 결과까지 8-bit로 내리지 않는다.
- ProRes 422로 원본의 더 높은 색차·비트 깊이·알파까지 모두 보존한다고 가정하지 않는다. 맞는 프로파일을 고르거나 지원 밖으로 표시한다.
- 원본 오디오의 채널과 의미 있는 트랙을 보존한다. ASR용 모노 오디오를 편집용 조각에 넣지 않는다.
- 지원하지 않는 데이터 트랙은 manifest에 기록한다. 불필요한 스트림 하나 때문에 영상·오디오를 조용히 누락하지 않는다.

### 8.3 시간 처리

- 내부 시간은 정수 PTS와 `time_base`, 또는 정확한 유리수로 표현한다. 누적 float 덧셈을 시각의 근거로 쓰지 않는다.
- 소스별 정규화 원점과 영상·오디오 시작 차이를 기록한다.
- CFR은 실제 프레임 경계에 맞춘다. VFR은 PTS를 기준으로 처리하고, 30fps로 조용히 바꾸지 않는다.
- VFR 정규화가 필요하면 명시적 변환 프로파일과 원본 대응표를 만든다. 지원하지 못하면 해당 조각을 차단한다.
- 조각의 로컬 재생 시각을 0부터 제공하되 영상·오디오의 **공통 기준 변환**을 적용한다. 두 스트림의 시작을 따로 0으로 만들어 상대 싱크를 없애지 않는다.
- 앞뒤 핸들이 있는 조각은 실제 추출 구간 기준의 로컬 시각과 본 구간 위치를 모두 기록한다.
- 출력 길이·첫/끝 프레임·오디오 시작 오프셋·디코딩 오류를 검증한다. 코덱 지연 및 샘플 반올림 허용치는 설정과 테스트로 명시한다.

### 8.4 순서와 검증

```text
segment_order=1 → 원본 구간 추출 → 출력 검증 → 게시
segment_order=2 → 원본 구간 추출 → 출력 검증 → 게시
segment_order=3 → ...
```

추출 작업은 `.partial` 또는 staging 경로에 쓰고, 성공·검증 후에만 최종 경로로 공개한다. 실패한 결과나 0바이트 영상은 편집용 목록에 넣지 않는다.

원본과 조각의 차이는 다음 두 층으로 검사한다.

- 구조 검사: 순서, 구간, 길이, 해상도, 채널, PTS, 파일 존재, 디코딩 가능 여부.
- 실기 검사: 경계 발화 잘림, 싱크, 화면 방향, Log/HDR 색 변화, 실제 Final Cut import.

구조 검사만 통과했다고 미디어 품질 실기 검사까지 통과했다고 표시하지 않는다.

### 9.2 정본과 파생 파일

- DB는 자산·순서·작업 상태·사용자 선택의 정본이다.
- 분석 JSON은 리비전별 불변 증거다. DB에는 위치와 지문을 저장한다.
- `clips.jsonl`, `clip_index.csv`는 package의 **불변 내보내기 snapshot**이다. DB와 동시에 수정되는 두 번째 정본으로 만들지 않는다.
- `cache/`, `previews/`는 지울 수 있지만 `originals/`, 확정된 `clips/`, `final/`, `subtitles/`는 일반 캐시 정리 대상이 아니다.
- 전체 작업공간을 다른 디스크로 옮겨도 다시 연결할 수 있도록 내부 경로는 프로젝트 루트 기준 상대 경로를 저장한다.

### 9.3 실제 편집 전달물

필수 전달물은 시간순의 실제 영상 파일과 `clip_index.csv`, `clips.jsonl`, 사용 안내다. CSV에는 다음을 포함한다.

```text
source_order,segment_order,clip_id,relative_path,source_id,source_filename,
core_start,core_end,media_start,media_end,duration,speech_summary,
visual_summary,tags,review_status
```

CSV 셀의 모델 출력이 수식으로 실행되지 않도록 수식 주입 방지를 적용한다. 한국어 파일명·공백·Unicode 정규화와 긴 경로를 테스트한다.

### 9.4 Final Cut에 가져가는 방식

이번 구현의 연결 지점은 **Finder에서 편집용 폴더 또는 파일을 가져오는 것**이다. Final Cut Pro는 Finder의 파일·폴더를 이벤트로 가져오는 흐름을 제공한다. [R12]

- UI에서 편집용 폴더 경로 복사 및 폴더 열기를 제공한다.
- 원본 이름이 중복되어도 경로와 번호로 구분할 수 있어야 한다.
- 영상마다 시간순 0-padding 번호를 유지한다.
- Final Cut 내부에서는 이름 정렬을 확인하도록 안내한다. 파일 번호가 있다고 외부 앱이 자동으로 원하는 순서의 타임라인을 만든다고 보장하지 않는다.
- FCPXML·라이브러리 DB·Apple event 자동 import·플러그인 설치는 요구하지 않는다.
- 편집기가 참조한 package 파일은 앱 종료·캐시 삭제·재분석 후에도 그대로 남아 있어야 한다.

## 10. ‘영상만’ / ‘영상 + 편집용 자막’ 모드

### 10.1 의미

```text
review_mode = "video_only" | "video_with_transcript"
```

두 모드는 **같은 원본, 같은 Luna 분석, 같은 구간 계획, 같은 편집용 영상**을 공유한다.

| 항목 | 영상만 보기 | 영상 + 편집용 자막 보기 |
|---|---|---|
| Luna의 장면·대화 이해 | 수행 | 수행 |
| 내부 음성 전사 | 수행 | 수행 |
| 플레이어 자막 오버레이 | 숨김 | 표시 |
| 전사 텍스트 패널 | 기본 숨김 | 표시 |
| 실제 편집용 영상 번인 | 하지 않음 | 하지 않음 |
| 최종 자막 생성 | 사용자가 최종 영상을 입력한 뒤 | 사용자가 최종 영상을 입력한 뒤 |

**`video_only`는 ‘영상만 분석’ 또는 ‘음성 인식을 생략’하는 모드가 아니다.** 대화 의미를 이해해야 하므로 내부 전사는 양쪽 모두 사용한다.

### 10.2 편집용 자막의 생성

- 이미 저장한 내부 전사에서 검토용 cue를 투영한다.
- 원본 시각에서 실제 조각 시작 시각을 빼고, 필요한 A/V 기준 오프셋을 적용한다.
- 브라우저 미리보기와 편집용 조각의 시간 대응이 다르면 해당 대응표를 사용한다.
- 경계에 걸친 cue는 표시 범위를 클립 내부로 제한하고 ‘경계 전사 확인’ 표시를 남긴다. 문장을 임의로 재작성하지 않는다.
- 초 단위 구간밖에 없으면 ‘구간 수준 전사’라고 표시하고 단어 수준 정확도를 암시하지 않는다.
- 검토용 자막은 `.review.vtt` 또는 `.review.srt`로 분리한다. 최종 자막으로 승격하지 않는다.

### 10.3 모드 전환의 비용·동작

- 전환만으로 API를 다시 호출하지 않는다.
- 선택된 조각·재생 위치·필터·사용자 검토 상태를 유지한다.
- 재인코딩하거나 파일명을 바꾸지 않는다.
- 저장된 전사가 없으면 ‘전사 없음/실패’를 표시한다. 모드 전환을 계기로 유료 호출을 조용히 시작하지 않는다.

모드는 우선 브라우저 안의 조각 검토에 적용한다. 외부 편집기용 검토 SRT는 선택 내보내기로 제공할 수 있지만, 개별 SRT가 Final Cut에서 영상에 자동 연결된다고 설명하지 않는다. 외부 앱의 자막 자동 부착 기능은 이번 범위 밖이다.

## 11. 최종 영상 기반 정밀 자막 — 최신 OpenAI 모델 통합

### 11.0 모델 선택의 근거와 제품 결정

**최신 전사 모델을 사용하는 것과 모델이 SRT를 직접 반환하는 것은 다른 요구다.** 2026-10-02에 확인한 OpenAI 공식 안내를 다음처럼 적용한다.

| 역할 / 기능 | 확인한 모델·인터페이스 | 이번 구현의 처리 |
|---|---|---|
| 최신 파일 전사 기본값 | `gpt-transcribe`; 공식 변경 이력의 출시일은 2026-07-28이다. [R15][R18] | 최종 오디오의 문구 전사·교정 입력으로 사용한다. |
| 단어/세그먼트 시간, SRT/VTT | 공식 기능 선택표는 `whisper-1`을 안내한다. [R16][R8] | 현재의 시간 골격 제공자로 사용한다. 신규 텍스트 모델의 시간 지원을 가정하지 않는다. |
| 라이브 입력 | `gpt-live-transcribe`가 실시간 흐름의 권장 모델이다. [R16] | 이미 완성된 영상의 파일 자막 작업에는 사용하지 않는다. |
| API 공통 출력 enum | 공통 API에는 SRT·JSON 등 여러 형식이 나열되지만 모델별 지원이 다르다. [R17] | enum에 `srt`가 있다는 이유만으로 모든 모델에 요청하지 않는다. |

**기본 프리셋:** `latest_openai_srt`.

```text
gpt-transcribe: 최종 오디오에서 실제로 들리는 문구
whisper-1:      같은 최종 오디오의 시간 골격(현재의 과도기 제공자)
앱:            대응 검증 → 안전한 문구 교정 → 조판 → 검토 → SRT/VTT
```

`gpt-transcribe` 단독으로 시간 정보까지 포함한 SRT를 직접 반환한다고 명세하지 않는다. 타임스탬프 없이 받은 문자열을 `.srt`로 저장하거나, Luna에 타임코드를 추측시키는 것은 요구 충족이 아니다. Whisper도 최신 모델이라고 표시하지 않는다.

이 조합의 품질 우위는 사용자 영상에서 아직 측정하지 않았다. 기존 엔진과의 비교 및 브라우저 실기 검토가 완료 기준이다. 실제 계정 접근 권한·유료 호출도 이번 문서 작성에서는 시험하지 않았다.

### 11.1 독립적인 새 입력과 실행 리비전

사용자가 외부 편집기에서 완성한 전체 영상 파일을 등록한다.

```text
final_video_revision = SHA-256(최종 영상 바이트)
caption_settings_hash = SHA-256(오디오 선택 + 추출 방식 + 모델 역할 + 힌트
                               + 타이밍/교정/조판 설정 + 기능 registry 리비전)
caption_run_id = 별도 실행 ID
```

- 실행 ID와 재사용 키는 다르다. 같은 입력·설정이어도 새 실행은 새 이력을 가진다.
- 최종 영상이 작업공간 밖에 있으면 검증된 사본을 보관한다. 이미 관리 중인 불변 사본이면 불필요하게 중복 복사하지 않는다.
- 같은 파일명을 덮어쓴 새 영상은 해시가 다르므로 새 리비전이다.
- FCPXML, 최종 타임라인 구조, 원본 조각의 사용 목록을 요구하지 않는다.
- 원본 분석 단계를 사용하지 않은 영상에도 최종 영상 하나만으로 이 기능을 사용할 수 있어야 한다.
- 최종 영상에 복수 오디오 트랙이 있으면 사용할 트랙/믹스를 사용자가 확인한다. 원본 편집 미디어의 트랙 구성은 수정하지 않는다.

### 11.2 첫 단계 결과를 재활용할 수 있는 범위

원본의 대화·장면 분석은 검색·편집 메모·검토용 정보로 보존한다. 최종 자막에는 사용자가 승인한 고유명사 힌트 정도만 선택적으로 활용한다.

다음은 금지한다.

- 원본 조각의 SRT를 단순 이어붙여 최종 SRT로 만들기.
- 실제 편집 순서를 모르는 상태에서 원본 타임코드를 최종 타임코드로 바꾸기.
- Luna의 장면 설명을 실제 발화처럼 자막에 쓰기.
- 원본 영상에 있었다는 이유로 최종 영상에서 들리지 않는 말을 복원하기.

완성 영상에는 조각 순서 변경·삭제·추가 내레이션·BGM·속도 변경·전환이 있을 수 있다. **최종 영상에서 실제로 들리는 오디오와 그 시간축이 기준**이다. 번역 자막이나 창작형 상황 자막은 이번 기본 기능이 아니다.

### 11.3 기본 실행 파이프라인

```text
최종 영상 조사·해시·오디오 트랙 확인
    → 모델 기능/수명주기/요청 설정 사전 검증
    → 비용 추정과 사용자 온라인 실행 승인
    → 최종 영상 시간축을 보존한 오디오 추출·분할
    ├→ 시간 경로: Whisper 세그먼트 → 기존 반복 오류 복구 → 불변 시간 골격
    └→ 문구 경로: gpt-transcribe 전사 JSON → 불변 문구 증거
    → 기존 retext 방식의 대응 검증과 제한된 문구 교정
    → 미대응·불일치·누락 의심 구간 보고
    → 줄바꿈·표시 길이·겹침 검사
    → 브라우저 플레이어·파형·자막 목록에서 검토/수정
    → 최종 영상 리비전별 SRT/VTT·trace·품질 보고서 저장
```

- 두 모델에는 동일한 오디오 추출본과 대응 가능한 청크를 보낸다. 오디오 해시·샘플 범위·요청 ID로 대응을 증명한다.
- `gpt-transcribe`를 단순 로그 표시용 검증에만 붙이지 않는다. 대응 검증을 통과한 문구는 실제 자막 교정 결과에 반영한다.
- 같은 청크의 문구 응답을 교정과 검증이 공유한다. 정상 경로에서 교정용과 검증용으로 같은 문구 모델을 두 번 부르지 않는다.
- 검증 기능은 경고만 추가한다. 같은 교정 결과에 대해 검증 on/off가 SRT 바이트를 바꾸지 않아야 한다.
- `latest_openai_srt`에서 최신 문구 모델이 실패하면 `partial_failure` 또는 명시적 초안이다. Whisper만으로 만든 결과를 최신 모델 적용 성공이라고 표시하지 않는다.
- 기본은 세그먼트 시간이다. `word` 시간은 별도 옵션·계약·추가 검증을 거친 경우에만 사용한다. 교정된 단어가 기존 단어와 다르면 옛 단어 시각을 그대로 재부착하지 않는다.

### 11.4 모델별 요청 어댑터

모든 실제 OpenAI 호출은 `vlogsrt/transcribe.py`의 좁은 전송 경계에 둔다. UI와 `raw/` 모듈은 타입이 있는 요청과 응답만 다룬다.

**문구 경로 — `gpt-transcribe`**

- `/v1/audio/transcriptions`를 사용하고, 기본 JSON 응답의 `text`와 실제 반환된 언어·사용량 정보를 읽는다. 없는 필드는 `null`로 둔다. [R8][R17]
- 예상 언어는 복수형 `languages`, 용어는 `keywords`, 문맥은 `prompt`로 전달한다. `language`와 `languages`를 함께 보내지 않는다. [R8]
- `timestamp_granularities`, `verbose_json`, `srt`, `vtt`, 미확인 `logprobs` 등을 이 어댑터에 임의로 붙이지 않는다. 기능 등록표가 허용한 값만 전송한다.
- JSON 응답의 `text`가 있다는 사실은 단어/세그먼트 시각이 있다는 뜻이 아니다. 응답 도착 시각·stream delta 도착 시각도 발화 시각으로 사용하지 않는다.
- 한국어를 기본 예상 언어로 하되 영어 등 혼용 언어를 선택할 수 있게 한다. 사용자가 승인하지 않은 장면 요약을 prompt에 자동 주입하지 않는다.
- 힌트에 줄바꿈·제어문자·부적절한 문자가 있으면 전송 전에 검증한다. 고유명사 힌트가 들리지 않는 말을 생성하게 하지 않는지 시험한다.

다음은 **설정 예시가 아니라 요청 형식을 설명하는 코드 조각**이다. 실제 구현은 중앙 전송 경계, 비용 승인, 재시도/취소 처리로 감싸야 한다. 모델 리터럴은 설정 파일에만 둔다. [R8]

```python
with audio_path.open("rb") as audio_file:
    result = client.audio.transcriptions.create(
        model=caption_cfg.text_model,
        file=audio_file,
        extra_body={
            "languages": list(caption_cfg.languages),
            "keywords": list(caption_cfg.keywords),
        },
    )
```

설치된 SDK가 필드를 정식 지원하면 해당 필드를 사용한다. 지원하지 않는 버전에서는 공식 안내의 `extra_body` 경로를 사용하고, 두 경로로 같은 필드를 중복 전달하지 않는다. 비어 있는 힌트 필드는 필요에 따라 생략한다.

**시간 경로 — 현재 `whisper-1` 호환 어댑터**

- 같은 전사 엔드포인트에서 `response_format="verbose_json"`, `timestamp_granularities=["segment"]`를 사용한다. [R8][R17]
- 기존 Whisper의 prompt 금지 규칙, 반복 복구, 청크 오프셋 규칙을 유지한다. 새 문구 모델의 prompt·keywords를 공통 요청 딕셔너리로 복사하지 않는다.
- 기존 파이프라인에 `gpt-transcribe` 응답을 Whisper 응답처럼 넣지 않는다. `TimedTranscript`와 `TextTranscript`를 구분한다.
- 과거 호환 테스트에 SRT 직접 반환 경로가 필요하면 Whisper의 `srt` 형식을 별도 시험할 수 있다. 기본 실행에서는 이미 받은 구조화 응답으로 앱이 SRT를 조립하므로 SRT를 얻기 위해 같은 오디오를 추가 호출하지 않는다.

### 11.5 문구 대응과 시각 보호

현재 저장소의 Whisper 시간 골격·`retext` 교정 계약을 보존하면서 아래 규칙을 검증한다. [R5]

1. Whisper의 반복 복구가 끝나면 세그먼트 ID·시간 범위·원응답을 고정한다.
2. `gpt-transcribe`의 문구를 같은 청크의 시간 골격 문구와 **순서를 보존하는 텍스트 대응**으로 연결한다. 이것은 강제 정렬/음향 정렬이나 새로운 시각 추정이 아니다.
3. 대응이 충분한 세그먼트 안에서만 문구를 바꾸고, 모델 응답으로 `start/end`나 세그먼트 경계를 이동하지 않는다.
4. 문장 경계를 넘는 재작성, 부정어·금액·숫자·고유명사의 중대한 불일치는 검토 항목으로 남긴다. 자동 채택 기준은 설정과 fixture로 정의한다.
5. 최신 전사에만 있는 문구는 `unmapped_text`로 보존한다. 인접 cue에 몰아넣거나 문자 수에 비례해 시각을 만들지 않는다.
6. 미대응 구간은 실제 오디오 반복 재생과 수동 수정으로 해결한다. 추가 전사가 필요하면 해당 오디오 범위의 요청·시간 근거·추가 비용을 기록한다.
7. 시간 제공자가 새로 반환한 결과를 사용하려면 별도 재전사 revision으로 처리한다. 이미 확정한 spine을 교정 단계에서 수정하지 않는다.
8. 대응 실패 시 기존 문구를 임시 유지할 수 있으나 반드시 `review_required`와 원인을 표시한다. 사용자의 명시적 검토 없이 최신 문구 반영 완료라고 표시하지 않는다.

자동 cue에는 최소한 `timing_segment_ids`, `text_evidence_ids`, `text_source`, `timing_source`, `correction_status`를 연결한다. 원응답·자동 결과·수동 결과를 분리하여 원문과 변경 이유를 추적할 수 있어야 한다.

### 11.6 긴 영상, 청크, 타임라인 원점

- 파일 전사 API의 안내 한도는 요청당 25 MB이다. 앱 기본 상한은 여유를 둔 24,000,000 bytes로 하고 실제 인코딩 파일 크기로 확인한다. 길이 상한과 함께 적용한다. [R8]
- 청크 최대 180초는 기존 흐름과 맞춘 **앱의 기본값**이다. OpenAI의 공통 시간 제한이라고 설명하지 않는다. 모델별 출력 한계·응답 잘림 시험에 따라 더 작게 조정한다.
- 청크는 최종 오디오의 전체 범위를 빠짐없이 덮는다. VAD를 이유로 말이 적거나 배경음만 있는 구간을 전송 범위에서 조용히 빼지 않는다.
- 원본의 영상 조각과 자막 전사용 오디오 청크는 다른 개념이다. 최종본에 첫 단계 조각 순서를 다시 적용하지 않는다.
- 기본 청크는 검증된 비중첩 샘플 범위다. 경계 문맥이 필요한 재시도만 중첩을 허용하고 소유 구간과 증거를 기록한다.
- 중첩 재시도에서 같은 문구를 제거할 때는 중복 오디오 증거까지 확인한다. 사람이 실제로 같은 말을 반복한 경우를 텍스트 중복만으로 지우지 않는다.

```text
final_cue_time = audio_to_video_origin
                 + actual_chunk_start_sample / extracted_sample_rate
                 + provider_segment_time
```

위 식의 오프셋은 가정한 청크 길이나 요청 순서가 아니라 실제 추출 샘플·검증된 시간 대응에서 얻는다. 유리수로 계산하고 SRT/VTT 직렬화 시에만 밀리초로 반올림한다.

오디오가 영상보다 늦게 시작하면 그 차이를 한 번만 반영한다. 앞·중간 무음은 보존한다. 압축 지연·패딩·스트림 시작 차이를 기록하고, 기존 FCP 경로의 ‘48 kHz WAV와 XML 길이 동일’ 검사를 복사하지 않는다. 최종 영상이 바뀌면 기존 자막을 현재 결과로 노출하지 않는다.

### 11.7 자막 조판·브라우저 검토·내보내기

기존 조판 설정을 우선 재사용한다. 다음 수치는 신규 UI의 **초기 제안값**이며 모델 정확도 보장이 아니다.

- 기본 최대 2줄, 한 줄 18자 목표. 기존 한글 폭 계산과 호환하고 사용자 조정 가능하게 한다.
- 시작/끝 자동 이동은 기존 `refine`의 명시적 허용 범위 안에서만 수행한다.
- 문장이 길면 우선 줄바꿈한다. 시간 근거 없이 문장을 여러 cue로 분할하고 균등 시간을 배분하지 않는다. 안전하게 분리할 시간 근거가 없으면 길이 경고와 수동 분할 UI를 제공한다.
- 읽기 속도·너무 짧은 표시·과도한 겹침·최종 영상 범위 이탈을 검사한다. 텍스트를 줄이려고 발화를 자동 요약하지 않는다.
- 원래 언어로 받아쓴다. 영어 번역 엔드포인트를 한국어 자막 생성에 잘못 연결하지 않는다.

브라우저에는 최종 영상·오디오 파형·자막 행·미대응 문구를 연결한다. 행 클릭으로 이동, 문구·시각 수정, cue 분할/병합, 구간 반복 재생을 제공한다. `최신 전사 문구`, `시간 골격의 원문`, `채택 문구`를 비교할 수 있게 한다.

자동 결과는 불변이고 수동 변경은 별도 patch/revision이다. 수동 변경은 현재 최종 영상·자막 실행 revision에만 적용한다. 재생 시각을 밀리초로 표시한다고 자동 타이밍이 밀리초 정확도라고 주장하지 않는다.

내보내기는 다음처럼 나눈다.

```text
draft.ko.srt / draft.ko.vtt   # 검토 전 또는 일부 문제가 있는 결과
final.ko.srt / final.ko.vtt   # 입력 처리 완료 및 사용자 검토 확정 결과
caption_trace.json
alignment_report.json
quality_report.json
provider_snapshot.json
responses/<request_id>.json
manual_edits.jsonl
```

SRT는 UTF-8, 1부터 이어지는 번호, `HH:MM:SS,mmm --> HH:MM:SS,mmm`, cue 사이 빈 줄을 사용한다. VTT는 같은 cue 자료에서 별도 직렬화한다. 모든 `.srt`/`.vtt`는 재파싱 검사 후 staging에서 원자적으로 게시한다. 언어 코드·파일명은 설정을 따라 변경한다.

### 11.8 비용, 캐시, 재시도

2026-10-02 공식 모델 페이지 기준 파일 전사 요금은 `gpt-transcribe` $0.0045/분, Whisper $0.006/분이다. 현재 2경로를 각각 한 번 수행하는 기본 전사비는 약 $0.0105/분, 60분이면 약 $0.63이다. 추가 요청·복구·과금 반올림·세금 등은 이 산술 예시에 포함하지 않는다. [R15][R20]

- 이 산술값을 실행 비용 상한이라고 쓰지 않는다. 실집행은 청크별 요청 분량, 복구 허용 횟수, 재시도 예약 비용을 합산한다.
- 첫 단계 분석비·최종 자막비·추가 복구비를 분리한다. `price_snapshot`과 사용량을 저장하고 가격 미확인은 0원으로 처리하지 않는다.
- 텍스트/시간 응답별 캐시를 분리한다. 키에는 최종 영상·오디오·청크 해시, 모델/제공자, 모델 registry revision, 힌트, 요청 설정, schema를 넣는다.
- 별칭 모델이 실제로 어떤 snapshot을 사용했는지 제공자가 반환하면 기록한다. 반환하지 않으면 `null`로 두고 임의의 날짜형 모델 ID를 만들지 않는다.
- 새 실행에서 오래된 별칭 캐시를 자동 재사용하지 않는다. 같은 job의 명시적 재개와 새 전사 실행을 구분한다.
- 유효한 원응답이 있으면 조판 변경·수동 수정·표시 토글만으로 API를 다시 부르지 않는다.
- 청크 하나의 기본 처리 완료 후 교정과 검증은 같은 최신 문구 응답을 공유한다. 복구 횟수는 별도 설정으로 제한한다.
- timeout/429/5xx의 일시 오류에만 제한된 backoff를 사용한다. 400 파라미터 오류·401/403 인증/권한·모델 없음은 반복 비용을 발생시키지 말고 중단한다.
- SDK 자동 재시도와 앱 재시도를 중복하지 않는다. 성공 여부를 모르는 timeout을 ‘무과금 실패’라고 가정하지 않는다.

### 11.9 최신성·지원 기능 등록표

`latest`라는 문자열, 모델 이름의 숫자 순서 또는 모델 목록의 `created` 값만으로 자막 모델을 자동 선택하지 않는다. 공식 문서의 권장 용도·출력 기능을 확인하고 사용자 영상 검증을 거쳐 등록한다.

필수 레코드: `ModelCapabilitySnapshot`.

```text
model_id, role, endpoint, requested_response_format,
confirmed_supported_features, unsupported_or_unverified_features,
docs_checked_at, registry_revision, pricing_snapshot,
deprecation_notice_date, shutdown_date, source_urls,
account_access_status, integration_test_status
```

- 기본 문구 모델은 설정의 `gpt-transcribe`다. 날짜형 snapshot이 공식 확인되지 않으면 만들어 쓰지 않는다.
- 모델 목록 API에 보이는 것은 접근 후보 확인일 뿐 SRT/타임스탬프 지원 증명이 아니다.
- 초기 `account_access_status`와 `integration_test_status`는 미검증이다. 유료 사전 점검은 별도 승인으로만 실행한다.
- 신규 모델은 fixture/계약 검사를 먼저 통과하고, 승인된 소량 실음성으로 내용·타이밍·요금 검증 후 선택 가능하게 한다.
- 실행 중 공급자·모델·기능 표·요금이 바뀌면 새 추정·새 승인을 요구한다. 기존 job은 동결된 설정을 유지한다.
- 새 모델이 단독 SRT/시간 정보를 공식 지원하고 계약 검증을 통과하면 별도 프로파일로 전환할 수 있다. 그 가능성을 현재 지원 사실로 표시하지 않는다.

### 11.10 Whisper 과도기 의존성과 종료 대응

OpenAI의 최신 종료 공지는 2026-08-26에 `whisper-1` 및 구형 4o 전사 계열의 지원 종료를 예고하고 종료일을 **2027-02-26**으로 명시한다. 따라서 현재 구성을 영구 해법으로 취급하지 않는다. 구현 착수 및 배포 시 공식 공지를 다시 확인한다. [R19]

**이번에 구현할 범위**는 시간 제공자 인터페이스·수명주기 검사·명시적 실패 처리다. 아직 검증되지 않은 새 정렬 모델을 자동 도입하는 것이 아니다.

```text
TimingProvider
    input:  검증된 오디오 청크 + 시간 대응 + 승인된 설정
    output: 시간 범위·텍스트·증거 ID가 있는 TimedTranscript
    current_adapter: whisper_verbose_json
```

- 사전 점검에서 `shutdown_date`, 접근 가능 상태, 필요한 출력 기능을 확인한다. 종료일의 정확한 시각을 가정하지 않는다.
- 앱 정책상 종료 예정 날짜에 도달하면 신규 온라인 Whisper 작업을 보수적으로 차단한다. 과거 유효 결과 열기·오프라인 fixture 재생·수동 수정은 계속 허용한다.
- 타이밍 모델이 사라져도 `gpt-transcribe` 문자열을 대충 시간을 나눠 SRT로 만들지 않는다. `TIMING_PROVIDER_UNAVAILABLE`을 표시하고 자동 최종 SRT 생성을 차단한다.
- 텍스트만 남기려면 사용자가 별도 전사 전용 실행으로 승인한다. 기존 SRT 작업 승인이 기능 축소 실행의 자동 승인은 아니다.
- 이후 공식 OpenAI 시간 정보 지원 모델이 나오면 교체 어댑터와 기존 회귀/사용자 영상 시험을 진행한다. 없으면 로컬 정렬 등 대안은 별도 요구·의존성·성능 검토로 결정한다.
- 첫 단계 내부 Whisper 전사도 같은 가용성 검사를 공유한다. 한쪽 경로만 업데이트하고 다른 경로를 잊지 않는다.
- 브라우저에는 ‘최신 문구 모델 + 레거시 시간 제공자’와 종료 경고를 표시한다. 모든 구성요소가 최신이라고 표시하지 않는다.

### 11.11 품질 상태와 완료 판정

`no_audio`, `confirmed_no_speech`, `partial_failure`, `review_required`, `ready`는 구분한다. 빈 문자열이나 빈 언어 배열 하나만으로 무발화를 확정하지 않는다. API 오류나 미처리 구간을 0바이트 SRT 성공으로 처리하지 않는다.

최소 검사 항목:

- `start < end`, 음수 없음, 최종 영상 범위 안의 시각.
- 청크 요청 coverage, 응답 누락/잘림, 과도한 반복.
- 최신 문구와 시간 골격의 대응 성공·거절·미대응 기록.
- 교정 전후 자동 시각 불변, 검증 on/off 결과 불변.
- 읽기 속도·줄바꿈·겹침 경고, 사람의 해결/허용 기록.
- 입력 해시·설정 리비전·자동 결과·수동 patch의 일치.
- 최신 문구 모델 호출이 실제 채택 경로에 연결되었는지와 실패 은폐 여부.

요청 coverage 100%는 모든 발화를 정확히 인식했다는 증거가 아니다. 무음에 cue가 없는 것은 정상이고, ASR 내용 정확도는 별도로 검토한다. 해결되지 않은 시간 근거·누락 처리 오류는 `final` 게시를 막는다. 경고를 사용자가 검토 후 허용하면 그 결정을 보고서에 남긴다.

### 화면 1 — 프로젝트 / 가져오기

```text
프로젝트: [새 프로젝트 / 기존 프로젝트 열기]
작업공간: [경로] [폴더 선택]
원본:     [SD 카드 선택] [원본 폴더 선택]

순서 | 파일명 | 촬영 시각 | 길이 | 해상도 | 용량 | 상태
000001 ...
000002 ...

[원본 순서 확인] [복사 및 검증]
완료 파일 수 / 전체 파일 수 · 복사량 · 오류 상세
```

파일 선택과 온라인 분석 시작을 분리한다. 이 화면에서 복사·조사만 했는데 API 비용이 발생하면 안 된다.

### 화면 2 — 분석 / 시간순 조각 검토

```text
[비용 예상 확인] [분석 및 시간순 조각 생성] [중지] [재개]

왼쪽: 원본 파일 목록 — 확정 순서
중앙: 현재 원본의 조각 목록 — 시간순 고정
오른쪽: 영상 플레이어 + 내용/장면/검토 메모

표시: (●) 영상만 보기  ( ) 영상 + 편집용 자막 보기
[이전 조각] [다음 조각] [원본의 해당 위치 보기]
[경계 조정] [분할] [다음 조각과 병합] [사용 / 제외]
```

- 시간순 번호, 원본 시작·끝, 길이, 생성·검토 상태를 항상 표시한다.
- 검색·태그 필터 후에도 결과는 원본 시간순이다. 관련도 점수가 순서를 바꾸지 않는다.
- 여러 원본 사이를 섞는 ‘중요도순 자동 배열’ 버튼은 넣지 않는다.
- 병합은 같은 원본의 연속한 본 구간에만 허용한다.
- 아직 추출되지 않은 항목을 완료된 파일처럼 다운로드·외부 편집 안내에 노출하지 않는다.

### 화면 3 — 편집용 폴더

```text
패키지: package_000001
[전체 조각] / [선택한 조각만]
프로파일: source_matched / edit_prores
핸들: 앞 [0.0]초 / 뒤 [0.0]초

[폴더 확정] [Finder에서 열기] [경로 복사]
원본 수 / 조각 수 / 전체 길이 / 사용 공간 / 검증 결과
```

여기서 보여주는 폴더는 임시 다운로드가 아니라 지속적으로 보관되는 편집 미디어다. ‘Finder에서 열기’는 사용자가 누른 경우에만 수행하고, OS 명령이 필요하면 기존 UI용 제한 경계에만 구현한다.

### 화면 4 — 최종 영상 / 자막

```text
최종 영상: [파일 선택 / 경로]
입력 리비전: <해시 요약> · 길이 · 오디오 트랙
자막 프리셋: 최신 OpenAI 기반 SRT (latest_openai_srt)
문구 모델: gpt-transcribe / 시간 제공자: whisper-1 (과도기)
공식 확인일 · 계정 접근 상태 · 시간 제공자 종료 경고
[예상 언어: 한국어 + 선택 언어] [고유명사 힌트]
[비용 예상: 문구 / 시간 / 복구] [정밀 자막 생성]

최종 영상 + 파형
시작 | 끝 | 채택 자막 | 문구 출처 | 시간 출처 | 검토 상태
[최신 전사 / 시간 골격 원문 비교] [미대응 문구만 보기]

[수정 저장] [초안 내보내기] [검토 확정]
[SRT 내보내기] [VTT 내보내기] [품질 보고서]
```

### 공통 UX

- 표시 언어는 한국어를 기본으로 한다.
- 긴 작업은 단계·파일 수·진행량을 보여주고, 오류는 해당 파일·구간으로 연결한다.
- 큰 목록은 페이지 또는 지연 로딩으로 처리한다.
- UI 선택 상태는 프로젝트별로 저장한다.
- 빈 작업공간, 카드 미연결, API 키 없음, 지원되지 않는 미디어에 대한 안내를 제공한다.
- 기본 워크플로를 실행하는 데 터미널 명령 입력을 요구하지 않는다. 터미널은 최초 실행과 진단용이다.

## 13. 데이터 계약

새 워크플로는 `raw-workspace/v1` namespace를 사용한다. 기존 FCP `ProjectRevision`, `ClipInstance`, `CaptionRequest`에 가짜 XML이나 가짜 타임라인을 넣어 재사용하지 않는다.

### 13.1 주요 레코드

| 레코드 | 필수 내용 |
|---|---|
| `SourceAsset` | 자산 ID, 원본 콘텐츠 해시, 크기, 작업공간 상대 경로, 원본 이름·출처, 미디어 조사 정보, 검증 상태 |
| `SourceOrderRevision` | 확정된 source ID 목록, 각 ordinal, 정렬 근거, 사용자 조정 이력 |
| `AnalysisWindow` | source ID, core/context 범위, 프레임·전사 증거 ID, 완료/실패 상태 |
| `SemanticAnnotation` | window ID, 대화·장면 요약, 태그, 경계 제안, 불확실성, 모델·프롬프트 리비전 |
| `SegmentPlan` | source ID, 정렬 리비전, 분할 리비전, segment ordinal, core/media 범위, 근거, 검토 상태 |
| `ClipArtifact` | segment ID, 추출 프로파일, 파일 경로·해시, 실제 미디어 길이, 시간 대응, 검증 결과 |
| `PackageRevision` | 정렬·분할·선택 리비전, 시간순 artifact 목록, 전체/선택본 구분, 완전성, 발행 시각 |
| `FinalVideoInput` | 최종 영상 경로·해시, 오디오 선택, 시간 원점, 오디오 해시, 입력 승인 |
| `CaptionRun` | final video revision, 설정 지문, text/timing 모델·profile·capability snapshot, 자동 자막·수동 변경·품질 보고서, 완료 상태 |
| `ModelCapabilitySnapshot` | 모델 역할·엔드포인트·확인 기능·문서 확인일·종료일·접근/실기 검증 상태·요금 리비전 |
| `TextTranscript` | 청크·오디오 해시, 문구·감지 언어, 실제 모델 응답·요청 ID·사용량. 시각 필드를 억지로 만들지 않는다. |
| `TimedTranscript` | 청크·오디오 해시, 시간 제공자, 세그먼트 범위와 증거 ID, 원래 시간 단위 및 오프셋 |
| `CaptionAlignmentReport` | 문구/시간 세그먼트 대응, 채택·거절·미대응 항목, 검토 조치 |
| `Job` | 작업 ID, 종류, 입력/설정 지문, 상태, 체크포인트, 사용량, 오류 |

ID는 파일명이나 표시 제목으로 만들지 않는다. 안정적인 콘텐츠·입력 구간·설정 지문을 사용한다. 조각의 표시 번호는 특정 순서/분할 리비전의 값이며, 자산 자체의 영구 신원과 구분한다.

```json
  "order_revision": "order_example_01",
  "source_order": 1,
  "segmentation_revision": "segments_example_01",
  "segment_id": "segment_example_02",
  "segment_order": 2,
  "time_base": {"num": 1, "den": 90000},
  "core_range": {"start_pts": 1116000, "end_pts": 2592000},
  "media_range": {"start_pts": 1116000, "end_pts": 2592000},
  "speech_status": "speech_detected",
  "speech_evidence_ids": ["utterance_example_12"],
  "visual_tags": ["walking", "talking"],
  "recommendation": "normal",
  "needs_review": false,
  "selection": "included",
  "export_status": "pending"

```

위 예시는 가상 데이터이며, PTS 범위는 원본의 12.4~28.8초를 나타낸다.

### 13.3 시각 불변 조건

- 모든 범위는 `[start,end)` 반개구간이다.
- source-local, clip-local, final-video-local 시각을 타입 또는 필드명으로 구별한다.
- source PTS 원점과 오디오 원점 차이는 한 번만 적용한다.
- 숫자가 문자열 타임코드로 보이는 것만으로 같은 시계라고 판단하지 않는다.
- JSON에는 유리수 분자·분모 또는 정수 tick을 저장하고, SRT 내보내기 마지막 단계에서 밀리초로 반올림한다.

## 14. 작업 상태, 캐시, 비용

### 14.1 작업 상태

```text
queued → running → succeeded
                ├→ cancel_requested → cancelled
                ├→ paused
                └→ failed
```

자산 준비, 분석 완료, 구간 계획, 조각 파일 준비, package 확정, 최종 자막 완료는 별도 상태로 저장한다. 전체 프로젝트 상태 문자열 하나로 모든 조각의 부분 실패를 숨기지 않는다.

- 브라우저 세션이 작업의 소유자가 되어서는 안 된다. 로컬 서버의 작업 관리자가 실행과 상태를 소유한다.
- 새로고침은 기존 job에 다시 연결한다. 버튼 재클릭으로 같은 일을 두 번 시작하지 않는다.
- 서버 재시작 후 실행 중이던 작업은 `interrupted` 사유의 재개 가능 상태로 복구한다.
- 작업 취소는 새 API 요청·새 추출을 멈춘다. 이미 끝난 유효 결과는 보존한다.
- 진행 중 API 요청이 취소되었다고 이미 발생한 비용이 취소되는 것으로 표시하지 않는다.
- 파일·DB 갱신은 트랜잭션 또는 원자적 게시로 처리한다. 중간 산출물을 완료 결과로 노출하지 않는다.

### 14.2 캐시 키와 재개

분석 캐시에는 최소한 다음 지문을 포함한다.

```text
source_sha256
+ audio_stream_selection / extraction_profile
+ window_range / frame_times / image_transform
+ ASR model / Luna model / request settings
+ prompt_revision / schema_version
```

추출 캐시는 원본 해시 + media range + 인코딩 프로파일 + 구현/도구 버전으로 분리한다. 자막 캐시는 최종 영상 해시 + 오디오 선택 + 청크 해시 + text/timing 모델 + 제공자/기능 registry 리비전 + 힌트 + 교정/조판 설정으로 분리한다. 최신 모델 별칭의 장기 캐시를 새 실행에 조용히 섞지 않는다(§11.8).

- UI의 자막 표시 모드는 분석·추출 캐시 키에 포함하지 않는다.
- 기존 엔진의 레거시 ‘실행마다 새 전사’ 동작은 그대로 두고, 신규 작업공간 워크플로의 명시적 캐시·재개와 구분한다.
- 캐시 재사용 전에 실제 파일 존재와 지문을 검사한다.
- 오류 응답을 정상 완료 캐시로 저장하지 않는다.
- 선택된 원본만 재분석, 변경된 구간만 재추출, 같은 최종본 자막 조판만 다시 실행하는 경로를 분리한다.

### 14.3 온라인 실행 승인

- 가져오기·원본 조사·로컬 구간 계획은 네트워크 없이 실행 가능해야 한다.
- 실제 AI 분석은 예상 음성 분량·이미지 수·사용 모델·추정 비용을 표시한 뒤 승인받는다.
- 가격은 모델/처리 방식과 확인 시각을 가진 snapshot으로 관리한다. 과거 코드의 이미지당 토큰 수를 새 모델에 그대로 적용하지 않는다.
- 확인되지 않은 가격은 0원으로 계산하지 않는다. 추정 불가 또는 사용자 제공 상한임을 구별한다.
- 비용 예산은 병렬 요청의 예약분까지 고려하여 집행한다.
- 첫 단계와 최종 자막의 비용을 나누어 표시한다. 두 번 처리하므로 항상 기존보다 저렴하다고 주장하지 않는다.
- 실행 중 모델·범위·설정이 바뀌면 새 추정과 승인을 요구한다.
- `VLOGSRT_OFFLINE` 또는 새 워크플로의 오프라인 설정을 UI가 우회하지 않는다.
- 오프라인 fixture 재생을 실제 API 분석 성공으로 표시하지 않는다.

### 14.4 개인정보와 저장 정책

- 외부 API로 보낼 음성·프레임·전사 범위를 사용자에게 설명한다.
- 원본 경로, 얼굴이 있는 프레임, 발화 내용이 로그나 내보내기 목록에 불필요하게 노출되지 않도록 한다.
- 공급자 보관 정책을 추정해 ‘전혀 저장되지 않는다’고 보장하지 않는다.
- API 키와 승인 정보는 영상 package에 포함하지 않는다.
- 모델 응답에는 개인정보가 들어갈 수 있으므로 디버그 공유 전에 확인하도록 안내한다.

## 15. 제안 모듈과 설정

아래 경로는 **새로 구현할 제안 구조**다. 현재 존재하는 파일 목록으로 오해하지 않는다. 파일 수 자체를 목표로 삼지 말고, 순수 계산과 외부 I/O의 경계를 기준으로 필요한 만큼 나눈다.

```text
vlogsrt/project/raw/
  models.py           # 새 입력·구간·artifact·job 계약
  workspace.py        # DB, 저장소, revision, 작업 상태
  ingest.py           # SD/폴더 가져오기와 체크섬 검증
  chronology.py       # 원본 순서와 안정적인 번호
  understanding.py    # 전사·프레임 증거 조합과 Luna 출력 검증
  segmentation.py     # 순수 시간순 분할 계획
  export.py           # 추출 요청 조립, 출력 검증, package 게시
  review.py           # 사용자 선택·경계 변경·편집용 자막 투영
  caption.py          # 최종 영상 → latest_openai_srt 실행 어댑터
  caption_models.py   # TextTranscript / TimedTranscript / AlignmentReport
  caption_policy.py   # 모델 기능·수명주기·문구/시각 분리 정책
  timing.py           # TimingProvider 인터페이스; 직접 SDK 호출 금지
  service.py          # UI와 CLI가 공유하는 공개 서비스
  commands.py         # 진단·자동화용 CLI

ui/
  app.py              # 기존 진입점 확장
  workspace_service.py
  components/         # 필요할 때만 플레이어·자막 검토 UI 분리

tests/raw/
  test_ingest.py
  test_chronology.py
  test_segmentation.py
  test_understanding.py
  test_clip_export.py
  test_review_mode.py
  test_final_video_caption.py
  test_caption_model_contract.py
  test_caption_alignment.py
  test_caption_lifecycle.py
  test_jobs_and_cache.py
  test_raw_e2e.py
```

새 workflow 설정은 `vlogsrt/project/config.py`의 독립 설정형으로 추가한다. Gradio는 기존 `ui` extra에, VAD 의존성은 기존 선택 영역에 유지한다. DB는 표준 라이브러리 `sqlite3`를 우선 사용한다. 새 UI 패키지 배포가 필요하면 현재 setuptools의 패키지 포함 범위도 검증한다. [R14]

### 15.1 설정 예시

다음은 목표 형식이다. 아래 CLI와 설정은 아직 구현된 인터페이스가 아니다.

```toml
[workflow]
schema_version = "raw-workspace/v1"
input_mode = "original_media"
source_workers = 1
export_workers = 1
```

## 16. Codex 구현 작업과 완료 기준

### A0 — 기존 계약 확인 및 방향 개정

읽을 파일: `CLAUDE.md`, `docs/PROJECT_CONTRACTS.md`, `README.md`, 기존 계획 3개, `ui/app.py`, `ui/service.py`, `vlogsrt/project/workflow_analysis.py`, `vlogsrt/project/final_caption.py`, 관련 테스트.

작업:

- 새 원본 워크플로가 기존 Final Cut 워크플로와 별도임을 문서화한다.
- Gradio 제거/플러그인 우선 계획에 새 방향으로 대체되는 범위를 명시한다. 과거 기록을 지우지는 않는다.
- UI → 새 서비스 진입점의 정확 경로 예외와 설정 계약을 추가한다.
- 최신 문구 모델·시간 제공자·문서 확인일·종료 예정일을 별도 설정으로 정의한다. 기존 `gpt-transcribe` 호출이 이미 있으면 새 구현이라고 중복 추가하지 말고 역할·파라미터를 점검한다.
- `make check` / `make invariant` 등 현재 검사 기준을 먼저 실행·기록한다.

완료 기준: 새 계약을 검사하는 테스트가 있고, 기존 원본 보호·호출 경계 검사가 유지된다. 기존에 실패하던 검사는 신규 변경과 구분한다.

### A1 — 작업공간과 최소 브라우저 흐름

- 프로젝트 생성·열기, DB schema/version, 설정 저장, job 상태를 만든다.
- Gradio 4화면 틀과 프로젝트 선택을 연결한다.
- 원본 경로 등록, 로컬 폴더 탐색, 파일 제공 범위 제한을 구현한다.

완료 기준: 새로고침·서버 재시작 후 프로젝트를 다시 열 수 있고, 허용되지 않은 파일은 브라우저에서 읽을 수 없다.

### A2 — SD/폴더 가져오기와 원본 순서

- 파일 발견·미디어 조사·용량 확인·검증 복사·중복 처리·원본 순서 확정을 구현한다.
- 원본 순서를 `SourceOrderRevision`으로 고정한다.
- 폴더 구조와 원본 출처를 보존한다.

완료 기준: 같은 파일명을 가진 서로 다른 원본이 덮어써지지 않고, 카드 분리/중단 이후 파일 단위로 재개된다. 카드 원본의 해시는 변하지 않는다.

### A3 — API 없는 시간순 분할·실제 추출 수직 통합

- synthetic 미디어와 결정적 경계 fixture로 전체 coverage 분할을 구현한다.
- 실제 MP4/MOV 파일을 번호순으로 추출·검증한다.
- package manifest와 CSV를 만든다.
- 순서 변경·경계 변경을 새 revision으로 처리한다.

완료 기준: **원본을 입력하면 시간순의 실제 조각 폴더가 생긴다.** 이 단계에서 metadata만 만들고 완료라고 하지 않는다. 루나 연결 전에도 원본 보존·순서·시간 검증을 자동 시험할 수 있다.

### A4 — 내부 ASR + Luna 의미 분석

- 첫 단계 전용 내부 전사 경계를 추가한다. 최종 자막 pipeline 호출과 분리한다. 시간 제공자의 가용성·종료 정책은 최종 자막 경로와 공유한다.
- 프레임·전사 증거 수집, Luna JSON schema, 경계 검증을 연결한다.
- 실패 시 보수적 유지와 검토 표시를 구현한다.
- 모델·프롬프트·범위 지문 기반 캐시와 비용 승인을 연결한다.

완료 기준: 말이 있는 장면과 풍경 모두 설명할 수 있고, 분석만 실행했을 때 최종 SRT가 만들어지지 않는다. 실제 API 테스트는 별도 비용 승인 후 진행한다.

### A5 — 브라우저 조각 검토와 두 표시 모드

- 시간순 목록·플레이어·내용 메모·태그 검색을 연결한다.
- 이전/다음, 분할, 같은 원본의 인접 병합, 사용/제외, 변경 revision을 구현한다.
- 검토용 VTT 투영과 자막 표시 토글을 구현한다.
- 재생 불가 포맷의 별도 미리보기를 연결한다.

완료 기준: 표시 토글 전후 API 호출 수와 영상 artifact 해시가 동일하다. 필터 후에도 시간순이며 새로고침 후 검토 상태를 유지한다.

### A6 — 편집용 package 확정

- 전체/선택본, 추출 프로파일, 핸들, 폴더 확정, 경로 복사/열기를 구현한다.
- 기존 package 덮어쓰기 금지와 캐시 정리 보호를 구현한다.
- 실제 Final Cut import 안내와 수동 인수표를 만든다.

완료 기준: 앱을 종료하거나 캐시를 지워도 확정한 조각이 정상 재생된다. 새 분석이 기존 편집 링크를 깨지 않는다.

### A7 — 최신 OpenAI 기반 최종 SRT와 브라우저 교정

A7은 모델명 한 줄 변경으로 완료하지 않는다. 다음 작은 작업 순서로 진행한다.

**A7-1: 기능 등록표와 역할별 요청 어댑터**

- `latest_openai_srt`, `TextTranscript`, `TimedTranscript`, `ModelCapabilitySnapshot`을 만든다.
- 문구 모델의 `languages`/`keywords`/JSON 처리, 시간 모델의 세그먼트 처리, 지원하지 않는 조합의 사전 차단을 구현한다.
- 모델 리터럴은 허용된 설정 경로에만 두고 실제 호출은 기존 전송 경계에 한정한다.

완료 기준: fixture 테스트가 두 경로의 요청 필드·응답 타입을 구분하고, `gpt-transcribe + srt/verbose_json/timestamp_granularities`의 무단 조합을 차단한다.

**A7-2: 최종 영상 오디오와 문구/시간 결합**

- FCPXML 없는 `FinalVideoInput`과 caption 어댑터를 구현한다.
- 실제 오디오 범위의 완전한 청크 처리, 원점·샘플 오프셋, 반복 복구를 연결한다.
- 최신 문구 응답을 `retext`의 검증된 교정 경로에 실제 반영하고 검증 단계에서 재사용한다.
- 미대응 텍스트/중대한 불일치/복구 실패를 숨기지 않는다.

완료 기준: fixture의 오인식 문구가 대응 검증 후 교정되고, 시각은 골격과 일치한다. 미대응 문구에는 가짜 cue가 생기지 않는다. 검증 토글은 결과 바이트·추가 문구 호출 수를 바꾸지 않는다.

**A7-3: 검토 UI·자막 직렬화·리비전**

- 문구/시간 모델·검증 상태·요금 표시를 최종 자막 화면에 추가한다.
- 원문 비교, 미대응 항목 이동, 파형 반복 재생, 텍스트/시간 수정을 연결한다.
- 초안/확정 SRT·VTT, source trace, 수동 patch, 품질 보고서를 원자적으로 게시한다.

완료 기준: 최종 영상만으로 실행할 수 있고, 원본과 다른 편집 순서·새 내레이션을 따른다. 새 최종본에 예전 자막이나 수동 patch를 자동 적용하지 않는다. SRT 재파싱 검사가 통과한다.

**A7-4: 제공자 수명주기·회귀 비교**

- 첫 단계와 최종 단계에 공통 가용성/종료 경고와 차단을 적용한다.
- `TimingProvider` 교체 인터페이스를 만들되 미검증 대체 모델을 자동 활성화하지 않는다.
- 승인된 소량 영상에서 기존 엔진 대비 문구·타이밍·누락·호출 수·비용을 비교한다. 측정된 결과만 보고한다.

완료 기준: 제공자 부재/종료일/권한 오류에서 가짜 SRT·조용한 fallback이 없다. 미실행 유료·Mac 테스트를 완료라고 표시하지 않는다.

| 모델 요청 | 문구/시간 모델의 서로 다른 필드, legacy 필드 혼입 | 올바른 파라미터만 전송, 지원 미확인 조합은 호출 전 차단 |
| 최신 문구 채택 | 시간 골격에 오인식, 최신 전사에 교정 문구 | 검증된 세그먼트 문구 변경, 자동 시각 불변 |
| 문구 미대응 | Whisper가 놓친 문장, 순서·부정어·숫자 불일치 | 미대응 보고서·검토 표시, 임의 타임스탬프 없음 |
| 교정/검증 분리 | verify on/off, 같은 문구 응답 재사용 | SRT 바이트 동일, 정상 경로의 중복 전사 호출 없음 |
| 긴 오디오 | 25 MB 근접, 180초 초과, 응답 잘림 | 실제 파일 크기 기준 분할, coverage 추적, 잘림 성공 오판정 없음 |
| 반복 | 실제 반복 발화와 청크 문맥의 중복 | 전사를 텍스트 중복만으로 삭제하지 않음 |
| 모델 장애 | 400, 401/403, 404, 429, timeout | 제한된 재시도·비용 예약, 구형 모델로 조용한 전환 없음 |
| 종료 대응 | 공지 갱신, 종료 날짜, 타이밍 모델 접근 불가 | 경고/차단, 과거 결과 보존, 신규 가짜 SRT 없음 |
| 힌트/다국어 | 한국어+영어, 고유명사, 빈 감지 언어 | 원어 자막, 실제로 안 한 말 삽입/빈 언어=무발화 추론 없음 |
| 결과 추적 | 모델·힌트·오디오 트랙 변경, 새 실행/재개 | 새로운 설정 지문, 올바른 응답·수동 patch 연결 |
| SRT/VTT | 긴 시간·Unicode·쉼표/마침표 구분·0길이 cue | 포맷 재파싱 통과, 잘못된 시간은 final 게시 차단 |
| UI 보안 | 원본 루트 밖 미디어 요청, 비밀 파일, 외부 Origin | 접근·변경 차단, 키 비노출 |
| 비용 | 미승인 실행, offline, 예산 초과, 토글 | 유료 호출이 정책을 우회하지 않음 |

자동 테스트는 합성 미디어와 기록된 응답을 우선 사용한다. 실제 개인 영상과 유료 API로 테스트하려면 범위·비용 승인이 별도로 필요하다.

### 17.1 실제 사용자 환경의 최소 인수 시나리오

1. SD 카드의 원본 3개를 브라우저에서 선택하고 작업공간에 가져온다.
2. 촬영 순서를 확인하고 원본 1부터 마지막 원본까지 조각을 생성한다.
3. 각 원본의 처음·중간·마지막 조각에서 순서, 발화 경계, A/V 싱크를 확인한다.
4. 자막 표시를 여러 번 토글하고 API 호출이 추가되지 않는지 확인한다.
5. 폴더를 확정하고 Finder에서 Final Cut으로 가져온다. 파일명 순서와 실제 재생을 확인한다.
6. 사용자가 조각을 선택·재배열한 최종 영상을 내보낸다.
7. 그 최종 영상을 브라우저에 등록하고 `latest_openai_srt`의 문구/시간 모델·추정 비용·종료 경고를 확인한 뒤 자막을 생성한다. 시작·중간·끝의 싱크, 고유명사·혼용 언어, 미대응 문구를 검토하고 SRT로 내보낸다.
8. 최종본을 수정해 같은 이름으로 다시 등록했을 때 새 자막 리비전으로 분리되는지 확인한다.

## 18. 완료 정의와 범위 밖

### 완료 정의

**별도 Final Cut 플러그인이나 XML 없이, 브라우저에서 SD 카드 가져오기 → 원본 내 시간순 실제 조각 생성 → 폴더 전달 → 완성 영상 입력 → 정밀 자막 검토·내보내기를 수행할 수 있어야 한다.**

첫 단계의 핵심은 대화·장면의 의미 이해이며, 최종 자막은 완성 영상에서 새로 만든다. v2 완료에는 최신 문구 모델의 실제 교정 반영, 검증된 타임스탬프, 지원 기능·수명주기 검사, 초안/확정 내보내기까지 포함한다. 기본 조각 순서와 원본 보존은 사용자의 표시 모드나 모델 판단으로 바뀌지 않는다.

### 이번 범위 밖

- FCPXML import/export, Final Cut Workflow Extension, Apple event 자동 import, 라이브러리 DB 수정.
- 완성 영상 자동 조립, 이야기 재배열, 멀티캠 동기화, 자동 음악 삽입.
- 클라우드 웹 서비스·팀 협업·계정·결제·원본 전체 업로드 시스템.
- 원본 삭제·SD 카드 포맷, 자동 색보정·LUT 번인·속도 변경.
- 프레임 정확 스마트 렌더, 새로운 forced alignment 엔진의 실제 도입, 원본-완성본 자동 타임라인 복원. 단, 시간 제공자 교체 인터페이스와 종료 대응은 이번 범위에 포함한다.

### Codex에게 전달할 시작 문구

> 이 문서를 이번 변경의 구현 계획으로 사용하라. 먼저 현재 브랜치와 기존 테스트 상태를 확인하고 A0부터 진행하라. 기존 Final Cut 기능은 호환 영역으로 보존하되 신규 워크플로는 FCPXML 없이 동작해야 한다. 시간순의 실제 영상 조각 생성과 원본 보존을 최우선으로 구현하고, Gradio 브라우저 UI에서 모든 주요 단계를 조작할 수 있게 하라. 첫 단계의 내부 전사·Luna 의미 분석을 최종 자막 생성과 분리하라. 최종 자막은 §11과 A7의 latest_openai_srt 계약대로 gpt-transcribe 문구와 검증된 시간 골격을 결합하여 만들어라. 최신 문구 모델에 미지원 타임스탬프/SRT 요청을 보내거나 시각을 추측하지 마라. Whisper는 과도기 시간 제공자이므로 공식 종료 공지를 재확인하고 가용성·교체 경계를 구현하라. 단계별 변경과 검증 결과를 기록하고, 실행하지 못한 실기 검사를 통과했다고 보고하지 마라. 이 문서만으로 유료 API 테스트나 원본 삭제를 승인받았다고 간주하지 마라.
