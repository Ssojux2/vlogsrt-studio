# STAB-TEST-ISOLATION — prerequisite before the next broad suite

Status: **planned, not executed in S2A-1**. Parent instruction `msg_c172e135f623` requires this boundary before another broad suite. Keep production configuration defaults unchanged. Sol coordinates and validates; Claude-GLM writes test code under a fresh Dispatch.

## Established evidence
- `vlogsrt/cli.py:main` calls `env.ensure_loaded()` on every CLI entry. `vlogsrt/env.py:find_env_file` searches cwd ancestors, then the resolved package root. `VLOGSRT_OFFLINE=1` does not suppress dotenv loading.
- `tests/conftest.py` blocks sockets and sets offline/log-level environment values, but does not isolate dotenv lookup. In-process entrypoint tests change cwd yet retain the package fallback. Existing installer subprocess tests execute a wrapper that changes into the real repository.
- Earlier broad/bridge runs invoked these paths. Whether a protected file existed or was read is deliberately not investigated. No protected contents may be inspected to establish that fact.
- S2A-1's final Swift real-wrapper test now copies only public Python source files and the byte-identical engine script into a temporary repository, uses a test-authored offline dotenv fixture to stop ancestor lookup, and invokes the real interpreter through an exec shim. Reuse this isolation principle, not the earlier real-root test setup.

## Bounded task and decisions
1. Before running a broad suite, map only the affected test entrypoints and subprocess environments. Candidate owned paths: `tests/conftest.py`, `tests/test_env.py`, `tests/project/test_engine_entrypoint.py`, `tests/project/test_engine_execution_lock.py`, `tests/project/test_development_engine_installer.py`, plus at most one test helper. Expected bound: six test files, three test modules; report immutable Impact and request Sol's bounded decision if findings exceed it.
2. Add test-only controlled configuration and a read/probe guard for real protected paths. The guard must not read or stat a protected file to decide whether it is protected. It must also cover subprocess paths, not just monkeypatch the pytest parent. Synthetic dotenv fixtures authored by the tests remain valid; tests of the real loader must still exercise production search/parsing semantics against those fixtures.
3. Prefer injected synthetic configuration for in-process tests and an isolated source/cwd/config layout for real CLI/installed-wrapper subprocesses. Prevent editable-package fallback into the live repository. Do not add a production bypass flag, change credential behavior, copy a real dotenv, or disable assertions/network guards. Limit public-source copies by an explicit file-type/path allowlist.
4. Prove the guard with a synthetic stand-in for a protected path containing an arbitrary canary; assert an attempted lookup/read is blocked without displaying the canary. Prove actual CLI and generated-wrapper runs use synthetic configuration and preserve their success/failure/cancellation assertions. Confirm dotenv unit tests still detect real loader bugs.
5. Once scoped checks prove isolation, Sol approves the guarded aggregate command and independently runs it. Capture original exits and import/cwd provenance. Do not rerun the prior unisolated command merely to compare counts. Record any test failures caused by isolation separately from product regressions; never weaken checks to restore a count.
