## Current API and required decisions
- `EngineRequestGate.perform` in `main.swift` owns the request before staging/state writes. Keep it outermost and retain `EngineSessionRunner` cancellation, revision, duplicate-exit and diagnostic-only sync contracts.
- `KeychainStore.save/load` currently has no injectable UI model and save deletes before insertion. Add a small injected storage abstraction; retain the existing public account/service defaults, preserve the previous key on failed replacement where the platform operation allows it, and never echo arbitrary storage errors containing submitted values. UI uses secure input, rejects whitespace-only input, clears submitted text on successful save, and displays saved/missing/failed status without showing any key. Fake storage is mandatory in tests; do not call Security services from tests.
- `BundledEngineInvocation` already passes an explicit child environment. `DevelopmentEngineInvocation` currently lacks a credential carrier and `NSUserUnixTask` has no per-task environment setter. Use a private bounded stdin pipe/envelope (or demonstrate an equally private supported per-task channel); no temporary secret file, argv value, parent `setenv`, defaults or JSONL. Ensure writer/read ends close on startup failure and completion, avoid pipe-capacity hangs, and make malformed/oversized input fail closed. An explicit no-key invocation must not resurrect a stale inherited key. Keep legacy direct 3/4-argument entrypoint behavior unless explicitly using the new carrier contract.
- The Python carrier currently sets `OPENAI_API_KEY` only if absent: replacement must override stale inherited values for app launches, before SDK/config resolution. Tests must prove the selected synthetic key reaches the SDK factory/consumer, not merely that the invocation object contains it. Bound any error sanitization to this credential boundary or existing diagnostic producers that can persist/print it; assert raw and SDK-style echoed submitted values are absent from stderr, user-facing errors, status artifacts and persisted job records.
- `analyze` currently means key-free inspect when no authorization exists, paid analysis when staged authorization exists. Preserve that contract, with required key only for the paid path; roughcut remains key-free. Do not add caption/progress/import operations. Revalidate actual prerequisites at execution; a cached estimate is not permission to bypass checks for paid work.
- Share a testable readiness result with the actual caller, not a disconnected UI helper. Validate safe job/input/selection, the selected executable, launcher-specific tool paths, readable media, grant coverage, started scopes and writable destinations. Start security scopes before protected reads; release partial acquisitions on all failures and retain successful scopes through execution. The development workspace scope is included. A missing prerequisite names corrective action and prevents execution/API/import; an unavailable bundled Release cannot silently choose development.
- Development readiness must reflect the installed wrapper's actual interpreter/tool environment, not a guessed app PATH. A read-only engine readiness operation/response is permitted if necessary, with no paid calls or job mutations and with the same guard/carrier/status contracts. Do not invoke an unguarded real-cwd wrapper in tests. Bundled readiness must not mask missing bundled tools with Homebrew fallback.
- Probe actual referenced sources for more than one audio stream before paid analysis. XML declarations alone are insufficient. Multi-audio fails closed with an actionable unsupported-topology reason; probe failure is an error, never silence. Preserve legacy supported mono/single-stream and zero-audio behavior, failed-range preservation, and estimates without a key. Use synthetic probe responses/media only. Existing `probe_source_summary`/runner/project checks may be reused where their semantics match.
