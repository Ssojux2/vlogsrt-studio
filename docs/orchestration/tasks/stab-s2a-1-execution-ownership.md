## Observable outcome and bounded ownership
- Canonical same-job requests execute once across concurrent app requests and independent Python processes. A rejected duplicate explicitly reports already-running, executes no API/import/staging, and leaves the legitimate attempt, cancellation and diagnostics untouched.
- Python target: macos/scripts/vlogsrt-engine.py and a small lock module only if justified. Swift target: FinalCutAgentCore request ownership and actual FinalCutAgentApp/main.swift caller. Tests target synthetic entrypoint subprocesses and Swift caller orchestration. EngineSessionRunner changes are allowed only to preserve/propagate this ownership contract.
- No credentials, preflight redesign, progress polling, budget/cache, or import lifecycle features. No new dependency. Preserve accepted S1 cancellation/drift checks, result binding, failure diagnostics and legacy behavior.

## Implementation decisions
1. Use a nonblocking OS advisory lock keyed by the canonical resolved job directory, not operation or caller job_id spelling. Acquire before workspace creation, staging, environment setup tied to a job, workflow/attempt/result writes or engine calls. Validating argv and resolving identity are read-only prerequisites. The lock file itself may be created in the already existing job directory; do not unlink it on release, which can split contention across inodes. Reject invalid/nonexistent job roots cleanly without manufacturing a workspace before ownership.
2. Symlink and relative aliases of the same directory must collide; different directories remain independent even when the textual job_id is the same. Keep the descriptor for the complete operation and result sync. Release on exceptions, nonzero return, cancellation and process exit/crash without stale PID/sentinel logic. Prevent lock descriptor inheritance from leaving ownership in an unrelated child after engine exit.
3. Reserve entrypoint exit 3 and a fixed sanitized already-running diagnostic for duplicate ownership. This is neither successful analysis nor a failed analysis attempt: do not write/sync aggregate failure, usage or attempt history for the duplicate. Swift maps it to an explicit alreadyRunning outcome before syncing any results or importing.
4. Add a testable per-job Swift request gate/coordinator that main.swift actually uses. Claim synchronously/atomically before bookmark/job staging, cancellation reset, state writes, executor launch or import. Hold through the full request including result handling/import, and defer release for success, thrown setup/executor errors, nonzero exit and cancellation. Avoid an untested helper or gate that starts only inside EngineSessionRunner after app staging. Canonical directory aliases share identity and distinct jobs can overlap; no global busy lock.
5. A duplicate must not replace current ownership, clear another job's cancellation handle, import a stale roughcut, or cancel/terminate the first process. If existing single currentEngineJob storage needs a bounded per-job ownership correction, explain it explicitly; broader cancellation UI redesign is excluded.

## Required behavioral proof
- Write regression tests first; before changing product code run the actual boundary regression, then use task-bound ask to let Sol independently reproduce RED. A missing import or missing symbol alone is not the required behavioral failure. A test may exercise the baseline caller/entrypoint using existing APIs and only later gain new result assertions.
- Python tests spawn the real executable script through sys.executable, not merely import main or invoke a lock helper. Use isolated synthetic Python modules/configuration or a controlled fake CLI to block at the first downstream engine call without live APIs. No production test-only environment switch. Assert first invocation reaches execution, second same-job/alias exits promptly with code3 and no second execution or snapshot mutations; a distinct job proceeds while the first is held. Assert clean release after failure, cancellation and process kill/crash, then successful reacquisition; use synchronization rather than timing guesses and always reap processes.
- Swift tests exercise the request orchestration called by main.swift with blocking/counting injected execution, staging and import callbacks. Concurrent duplicate must yield one stage/executor/import, preserve first ownership, and return alreadyRunning. Cover canonical aliases, distinct-job overlap, setup/executor failure, cancellation and subsequent reacquisition; nonzero Python duplicate must not sync/import. Verify actual main.swift wiring by review and an integration regression where feasible, not just textual helper existence.
- Preserve fresh entrypoint, S1 live-cancel, result binding and diagnostic tests. Use explicit synthetic settings; never inspect .env/.env.example/credentials or touch real API fixtures/media.
- No shared-checkout stash/reset/source swaps for baseline. Isolated historical owned files are allowed; record their import origins. Capture original command exit before any log tail/grep. Targeted checks first, then one final make check, Swift suite and engine-script Ruff check/format (uncovered by Makefile); reuse untouched evidence after any Swift-only correction.
