## D1. `docs/PLAN.md` 없이 구현했다

`CLAUDE.md`와 `TASKS.md`가 `docs/PLAN.md`의 섹션을 참조하지만 그 파일은 저장소에 없다.

**영향**: PLAN에만 적혀 있었을 세부 규칙(예: §6.6 고아 처리의 정확한 절차,
§6.8 이상치 검사 항목 전체 목록)은 이 문서의 판단으로 대체했다. 아래 D4, D6이 그것이다.
PLAN이 나타나면 이 세 항목을 대조해야 한다.

## D3. `Cue.text`는 속성, `text_raw`는 두지 않았다

문서는 `cue.text_raw`를 언급하지만, 줄 목록(`lines`)에서 한 줄로 잇는 속성 하나면 충분했다.

## D4. 고아 처리는 "전체 골격 재사상"으로 풀었다

**문제**: `build_w`는 `verdict != ok` 세그먼트를 뺀다. 그러면 그 시간대의 gpt 텍스트는
정렬에서 `insert` 블록이 되어 이웃 큐에 통째로 흡수된다. 텍스트는 살아남지만 **엉뚱한 시각에 뜬다.**

**해법**: `rescue_orphans`가 제외 세그먼트를 **포함한** W로 한 번 더 정렬한다
(`build_w(spine, include_all=True)`). 제외 세그먼트가 차지한 A 구간을 잘라내
고아 큐로 만들고, 그 텍스트가 이웃 큐에 흡수돼 있으면 거기서 뺀다(중복 방지).

고아 큐의 시각은 제외 세그먼트 자신의 `start`/`end`다 — 추정이지만 근거 있는 추정이다.
`conf`는 `orphan_conf_max`(0.30)로 고정하고 `time_estimated` 플래그를 단다.

**한계**: 이웃 큐에서 텍스트를 뺄 때 부분 문자열 일치를 쓴다. 같은 문장이 두 번 나오면
엉뚱한 쪽에서 뺄 수 있다. `tests/test_mapping.py::test_orphan`이 중복 없음을 검사한다.

## D5. `insert` 블록의 절단점은 `j1`로 보낸다

`map_position`이 `insert`/`delete` 블록 안에 떨어지면 `j1`을 돌려준다.
다만 자모 단위 정렬에서는 `insert` 블록이 음절 중간에 생기는 일이 흔해,
실제 결과는 어느 쪽으로든 한 음절 이내에서 갈린다. 그 뒤 어절 스냅이 정리한다.

`tests/fixtures/synthetic/map_cases.json`이 16개 케이스의 결과를 못 박아 뒀다.
이 값이 바뀌면 정렬 동작이 바뀐 것이다.

## D6. 이상치 검사 항목 (PLAN §6.8 대체)

| 수준 | 코드 | 뜻 |
|---|---|---|
| ERR | `bad_range` | `end <= start` |
| ERR | `empty_text` | 텍스트 없음 |
| ERR | `overlap` | 앞 큐와 겹침 |
| ERR | `too_many_lines` | `max_lines` 초과 |
| ERR | `unknown_seg` | 골격에 없는 `seg_id` |
| WARN | `line_too_wide` `too_short` `too_long` `cps` `tight_gap` `low_conf` `no_origin` `out_of_spine` | 기록만 |
| INFO | `orphan` `flag:*` | 참고 |

`ERR`은 파이프라인이 고친다(시간 보정 → 충돌 해소 → 빈 큐 제거).
정상 실행에서 `ERR`은 0이어야 한다.

## D12. TASKS.md §T3.1의 gpt 호출 파라미터가 틀렸다 (실측)

TASKS.md는 `gpt-transcribe` 호출에 `language`와 `languages`를 **둘 다** 넘기라고
적어두었다. 실제 API는 400을 돌려준다.

```
The 'language' and 'languages' parameters cannot be used together.
```

여러 언어를 알려주는 쪽이 이 프로젝트의 의도(한국어 브이로그 + 영어 상호명)라
`languages`를 택했고, `extra_languages`가 비어 있을 때만 단일 `language`로 떨어진다.
**임계값이 아니라 API 계약이라 고쳤다.** 근거는 실측 응답이고
`tests/test_transcribe.py`가 조합을 못 박는다.

### 곁들여 드러난 것: 반쪽 녹화

whisper는 성공하고 gpt가 이 400으로 죽었다. `record_fixtures`가 dict 리터럴
순서대로 whisper를 먼저 저장했기 때문에 `*.whisper.json` 만 남았다. 그런데

- `has_fixture()` 가 whisper만 확인해서 "녹화됨"으로 판정 → 녹화를 건너뛰고
  곧바로 없는 gpt 픽스처를 찾다가 실패
- 다시 녹화하면 성공한 whisper까지 재결제 (77분이면 약 $0.46)

둘 다 고쳤다. `has_fixture()` 는 두 모델 응답이 **모두** 있어야 참이고,
`record_fixtures(reuse_existing=True)` 는 이미 있는 응답을 다시 부르지 않는다.

## D11. gradio UI는 패키지 **밖**에 둔다

불변 규칙 7은 의존성을 `openai`, `tomli-w`, `rich` 셋으로 못 박는다. 웹 UI 요청이
들어왔을 때 선택지는 셋이었다.

1. `vlogsrt/`에 gradio를 넣는다 → 규칙 7 위반. 핵심 파이프라인이 무거워지고,
   `make check`가 UI 설치 여부에 흔들린다
2. UI를 만들지 않는다 → 사용자의 실제 요구를 거절하는 것
3. **UI를 `ui/`에 두고 선택적 extra로 만든다** ← 선택

`ui/`는 vlogsrt를 라이브러리로 쓰고, `vlogsrt/`는 gradio를 모른다.
`[project.dependencies]`는 그대로 3개이며, gradio는 `[project.optional-dependencies] ui`에 있다.
`scripts/check_invariants.py`가 `vlogsrt/`의 gradio import를 금지 목록으로 막는다.

`ui/service.py`(순수 로직)와 `ui/app.py`(화면)를 가른 이유도 같다.
service는 gradio를 import하지 않아 UI 없이도 테스트가 돈다.

### 화면은 세 개로 줄였다

처음에는 슬라이더·탭·미리보기·재조판까지 넣었는데, 쓰는 사람이 원한 것은
**경로 입력 · 실행 로그 · SRT** 셋뿐이었다. 나머지는 걷어냈다.
조판 조정은 `vlogsrt redo`가 이미 더 잘한다 — 화면에 두 번 만들 이유가 없다.
`make_subtitles()`는 예외를 던지지 않고 전부 로그 문자열로 돌려준다.
빨간 토스트보다 로그 한 칸이 읽기 쉽다.

### 파일 고르기는 서버 쪽 네이티브 대화상자로 간다

세 번 갈아탔다. 기록해 둘 값어치가 있다.

1. `gr.FileExplorer` — **파일이 하나도 안 보였다.** glob을 `**/*.{mp4,mov,...}` 로
   줬는데 gradio는 `fnmatch`로 매칭하고, `fnmatch`는 중괄호 확장을 지원하지 않는다.
2. `gr.File` — OS 대화상자는 열리지만 브라우저가 **실제 경로를 안 준다**(`C:\fakepath\...`).
   파일이 통째로 서버로 올라오고(복사), 원본 폴더를 알 수 없어 SRT를 옆에 못 둔다.
3. **`osascript`로 서버에서 대화상자를 연다** ← 현재.
   서버가 곧 이 컴퓨터라서 가능한 방법이다. 진짜 경로가 오고, 복사가 없고,
   큰 영상도 즉시 시작된다.

대가: macOS 전용이고, `--share` 로 남에게 열어주면 대화상자가 서버 컴퓨터에 뜬다.
개인 도구라 받아들일 만하다. 다른 OS에서는 경로 직접 입력으로 안내한다.

AppleScript를 문자열로 만들다 보니 조립 실수가 났다 — 플레이스홀더를 `{TYPES}` 로
두는 바람에 `.replace()` 가 중괄호까지 먹어 `of type "mp4", ...` 가 됐다.
문자열 검사로는 안 잡혀서, 테스트가 `osacompile` 로 **실제 컴파일**해 본다.

### 최종 SRT는 원본 영상 옆에

편집 프로그램에 넣을 때 영상과 같은 폴더에 있는 편이 손이 덜 간다.
SRT만 옆에 두고, 검토용·리포트·`trace.json`은 `out/<회차>/`에 남긴다 —
사람 폴더에 작업 부산물을 흘리지 않기 위해서다.

업로드본은 원본 폴더를 알 수 없어 `out/`에 둔다. 판정은 gradio 임시 폴더
아래인지로 하는데, macOS에서 `gettempdir()`는 `/var/folders/...`를 주고 실제
경로는 `/private/var/folders/...`라 **양쪽 다 resolve해야** 한다.
이걸 빠뜨렸을 때 SRT가 조용히 임시 폴더로 들어갔다.

### gradio 6에서 부딪힌 것

- `theme`/`css`가 `Blocks()`에서 `launch()`로 옮겨졌다
- `launch(show_api=...)`가 사라졌다
- `gr.Video`의 `postprocess`가 더 이상 `(video, subtitle)` 튜플을 받지 않는다
  (독스트링에는 남아 있지만 코드에는 없다). `gr.update(subtitles=경로)`도
  경로 문자열을 그대로 보내 프런트가 못 읽는다. **컴포넌트 인스턴스를 돌려주면**
  생성자가 SRT를 VTT로 바꿔 FileData로 감싸준다 — 그 경로를 썼다
- `no_site_packages = true`를 켰다. ui extra가 numpy를 끌어오는데 numpy 스텁이
  3.12 문법이라 `python_version = "3.11"` 설정으로는 파싱조차 실패했다.
  이제 mypy 결과가 무엇이 설치돼 있는지에 흔들리지 않는다

## D13 — 자막 어긋남의 원인은 절단이 아니라 whisper 전사였다

77분 영상(`fr_day_1_2_fhd`)의 SRT가 소리와 맞지 않는다는 신고. 첫 의심은
"모델에 들어가는 클립이 잘못 잘렸다"였다. **아니었다.** 실측으로 갈랐다.

절단 경로는 이상이 없다:

| 검사 | 결과 |
|---|---|
| ffmpeg `-i` 뒤 `-ss/-to` 출력 탐색 | 마커 오디오로 확인, 정확 |
| loudnorm 통과 후 타임라인 | 300초에서 오차 **0.000초** |
| 4조각 분할 후 로컬시각+오프셋 | 전 조각 일치 |
| 실제 청크 ↔ 전체 오디오 포락선 | 상관 0.9999 / 1.0000, 지연 **0.0초** |
| 영상 길이 ↔ 오디오 길이 | 차이 0.094초 |
| 골격 시각 ↔ 실제 소리(F1 최대화) | 최적 시프트 **0.0초** (단봉) |

원인은 whisper-1의 디코딩 붕괴다:

- **프롬프트 오염.** `vlogsrt.toml`의 `prompt`가 메타 지시문이었다
  (`"브이로그 내레이션입니다. 구어체 한국어이며 …"`). whisper는 `prompt`를 지시가
  아니라 **직전 자막 텍스트**로 보고 이어 쓴다. 그 결과 11.9초부터 582.3초까지
  570초 동안 `'구어체 한국어에서 한국어 자막을 사용합니다.'`를 103회 반복했다.
- **반복 루프.** 총 10구간 1134초 = 영상의 **24.7%**가 같은 문장 반복이다.
  청크가 38분씩이라 디코더가 뒤로 갈수록 무너진다(청크1 실패는 전부 후반부).
- **0길이 세그먼트** 1931개 중 452개(23.4%).

여기서 파이프라인의 구조적 약점이 드러났다:

1. `compression_ratio`는 **세그먼트 안쪽** 반복만 본다. whisper가 반복을 세그먼트
   단위로 쪼개면 각각은 압축률 0.97로 정상이라 그대로 통과한다. → `vlogsrt/loops.py`
2. 환청 판정으로 빠진 구간은 `rescue_orphans`가 되살리는데, 반복 구간은 정렬이
   무너져 **정본 텍스트 570초분이 큐 하나에 몰린다**. 0.77초 큐에 773자가 나온
   이유다. 뒤따르는 세그먼트는 0자가 되어 202개가 사라졌다.
3. 결과: SRT가 덮는 시간이 4598초 중 1915초(41.6%)뿐이다.

전역 유사도는 0.74라 `global_sim_floor = 0.4` 폴백에 걸리지 않았다. 전역 지표가
국소 붕괴를 못 본다. **국소 방어선이 없다.**

`scripts/verify_timing.py`(= `make verify STEM=<회차>`)가 이 표를 기계적으로 다시
만든다. API를 부르지 않고 녹화 픽스처와 전처리 캐시만 읽는다. 다음에 같은 신고가
오면 귀로 듣지 말고 이걸 돌린다.

## D14 — UI는 매번 새로 전사하고, SRT 말고는 아무것도 남기지 않는다

D13의 사고는 두 층이었다. whisper가 무너진 것이 하나고, **무너진 기록을 다음
실행이 조용히 재사용한 것**이 둘이다. 예전 UI는 이렇게 돌았다:

1. `has_fixture(stem)` 이 참이면 → "기록된 응답 재사용"
2. 거짓이면 → `record_fixtures()` 로 녹화 후 그걸 다시 읽어 오프라인 실행

파일 이름(`stem`)이 키였다. 같은 이름의 다른 영상을 넣어도 옛 응답을 썼고,
반쪽만 녹화된 상태도 있었다. 사람은 자기가 방금 넣은 영상의 자막을 본다고
믿는데 실제로는 지난주 응답을 보고 있을 수 있었다.

이제 UI 경로에서 픽스처를 아예 쓰지 않는다.

- `pipeline.run(..., online=True, artifacts=False, workdir=<임시폴더>)` 한 번으로 끝난다
- `artifacts=False` → `trace.json`·리포트·검토용 SRT·`output.srt` 별칭을 쓰지 않는다
- `reuse_cache=False` → 지문 폴더를 만들지 않고 오디오를 매번 새로 뽑는다
- 임시 폴더는 `TemporaryDirectory`라 끝나면 오디오·조각까지 함께 사라진다
- 남는 파일은 원본 영상 옆의 SRT 하나

`vlogsrt record` 는 그대로 둔다. 그건 **테스트 픽스처를 만드는 개발용 명령**이고,
`make verify`와 픽스처 우선 개발 규율이 거기 걸려 있다. 앱 경로와는 분리됐다.

키가 없으면 오디오를 뽑기 **전에** 멈춘다. 몇 분 기다린 뒤 인증 오류를 보는 것은
낭비다. 그리고 `openai`의 예외는 `RuntimeError`가 아니라서 예전에는 화면에
트레이스백이 그대로 튀었다 — 이제 `Exception`을 받아 한 줄로 보여준다.

### 청크 길이 상한

`chunk_max_seconds = 600.0` 을 새로 뒀다. 예전에는 업로드 한도(24MB)만 봤고,
64kbps 모노에서 24MB는 **약 50분**이다. 그래서 77분 영상이 38분짜리 두 조각이
됐고 whisper-1이 조각 후반부에서 반복 루프에 빠졌다. 이제 크기와 길이 중
**더 잘게 나누는 쪽**을 따른다(`preprocess.chunk_count`). 77분이면 8조각이다.

## D15 — whisper 힌트는 화면에서 매번 정한다

D13의 방아쇠는 `vlogsrt.toml`에 박아둔 한 줄이었다.

```toml
prompt = "브이로그 내레이션입니다. 구어체 한국어이며 상호명과 지명이 자주 나옵니다."
```

설정 파일에 있으니 아무도 다시 보지 않았고, 영상마다 맞지도 않았다. 이제 비워두고
실행할 때마다 화면에서 받는다. 무엇을 넣고 돌렸는지는 로그에 `힌트   …`로 남는다.

`prompt`가 위험한 이유를 화면 안내에 적었다. whisper는 이 값을 **지시가 아니라
직전 자막 텍스트로** 보고 이어 쓴다. 그래서 지시문을 넣으면 그 문장이 자막이 된다.
넣을 것은 나올 법한 **단어**다.

### 국소 방어선

전역 유사도(`global_sim_floor`)는 0.74였고 폴백에 걸리지 않았다. 전역 지표가
국소 붕괴를 못 본다는 게 D13의 교훈이었다. 그래서 골격을 만든 직후에
`pipeline.warn_about_loops()`가 반복 구간을 세어 알린다. 판정은 바꾸지 않는다 —
`spine[]`은 그대로 두고 보고만 한다(불변 규칙 1). 실측 픽스처에서는 이렇게 나온다:

```
경고 whisper가 같은 문장을 되풀이한 구간 10개 · 1134초 (영상의 24.7%)
경고   12~582초 · 103회 · '구어체 한국어에서 한국어 자막을 사용합니다.'
경고   영상 시작부터 반복한다면 whisper 힌트(prompt)를 의심하라.
```

길이 0인 세그먼트 경고도 한 줄씩 찍던 것을 한 번의 요약으로 바꿨다. 452줄이
쏟아지면 정작 봐야 할 경고가 묻힌다.

## D16 — whisper에는 prompt를 보내지 않는다

D15에서 힌트 칸을 만들었다. 사람이 `"프랑스 여행 브이로그"`라고 적었다.
지극히 자연스러운 입력이다. 결과:

```
힌트   프랑스 여행 브이로그
경고   whisper가 같은 문장을 되풀이한 구간 9개 · 675초 (영상의 14.7%)
경고     12~576초 · 138회 · '한국 여행 브이로그'
```

12초부터 576초까지, 즉 **0:12~9:36 전체**가 날아갔다. 최종 SRT의 첫 큐가
09:42에서 시작한 이유다. D15에서 넣은 경고가 원인을 정확히 지목했다는 점은
다행이지만, 경고로 막을 일이 아니었다.

핵심은 이것이다. **whisper 텍스트는 최종 SRT에 한 글자도 들어가지 않는다**
(불변 규칙 2). whisper에서 얻는 것은 골격 시각뿐이다. 그런데 `prompt`는
whisper에게 지시가 아니라 직전 자막 텍스트로 들어가서, 알아듣기 힘든 구간을
만나면 그 문장을 이어 쓴다. **얻는 것이 없고 잃는 것은 골격 전체다.**

두 번의 실측이 같은 말을 한다:

| prompt | 반복 문장 | 횟수 | 길이 |
|---|---|---|---|
| `"브이로그 내레이션입니다…"` | `'구어체 한국어에서 한국어 자막을 사용합니다.'` | 103회 | 570초 |
| `"프랑스 여행 브이로그"` | `'한국 여행 브이로그'` | 138회 | 564초 |

그래서 `LiveTranscriber.whisper()`는 `prompt`를 넘기지 않는다. 사람이 준 힌트는
`gpt()`로 간다 — 최종 SRT의 글자를 만드는 모델이라 힌트가 실제로 쓸모 있는 곳이다.
`prompt`가 거부되면(400) 부가 인자만 떼고 한 번 더 부른다. 그 시점엔 whisper
응답을 이미 받아둔 상태라, 여기서 죽으면 약 $0.46이 통째로 버려진다.

### 넘침 가드

whisper가 한 구간을 통째로 놓치면 그 구간 정본 텍스트는 얹을 시각이 없다.
`map_cuts`가 남은 글자를 다음 절단점까지 몰아주므로 1초짜리 큐에 900자가 들어간다.
읽을 수 없는 자막이 되는 것으로 끝나지 않고 **멀쩡하던 이웃 큐까지** 밀려서
못 쓰게 된다 — 9분 공백이 4분치 정상 자막을 잡아먹었다.

`vlogsrt/overflow.py`가 큐 하나가 담을 수 있는 글자 수를 조판 한도와 읽기 속도
중 큰 쪽의 `overflow_factor`배로 제한한다. 넘치면 어절 경계에서 자르고 **얼마나
버렸는지 반드시 알린다.** 같은 픽스처로 재확인:

```
이전   큐 1019개  최대 881자  200자 넘는 큐 3개
지금   큐 1019개  최대  96자  200자 넘는 큐 0개
경고   정렬이 무너진 큐 5개에서 정본 1730자를 버렸다.
```

### 저역 제거를 정규화 앞에

문제의 앞 9분은 200Hz 아래 웅웅거림이 에너지의 절반이었다. 그 상태로 loudnorm을
걸면 **잡음에 맞춰 이득이 정해져 말소리가 오히려 눌린다.** 사람 목소리 기본
주파수는 남성도 85Hz 위라 120Hz 아래에는 말소리 정보가 없다.

| | 음성대역(300~3400Hz) | 저역(<200Hz) | 음절변조 |
|---|---|---|---|
| 앞 300초 · loudnorm만 | 30.4% | 51.4% | 0.398 |
| 앞 300초 · highpass 후 | **58.6%** | 26.8% | 0.384 |
| 앞 480초 · loudnorm만 | 43.0% | 36.2% | 0.229 |
| 앞 480초 · highpass 후 | **61.9%** | 23.1% | **0.340** |
| 뒤 3000초 · loudnorm만 | 72.0% | 7.0% | 0.360 |
| 뒤 3000초 · highpass 후 | **86.1%** | 2.7% | 0.360 |

잘 들리던 뒤 구간도 나빠지지 않는다. 마커 오디오로 타임라인 보존도 확인했다
(300초에서 오차 0.02초).

### 무음 처리는 원인이 아니었다

신고는 "무음 구간 없애는 부분에 문제가 있는 것 같다"였다. 아니다.

- `extract_audio`도 `make_chunks`도 오디오를 **한 샘플도 버리지 않는다.**
  청크 계획은 `[0, cut1], [cut1, cut2], …, [cutN, duration]`으로 전 구간을 덮는다
- 무음은 두 곳에만 쓰인다: 청크 절단점 고르기, `silent` 판정
- 실측에서 `silent` 판정을 받은 세그먼트는 **0개**였다 (ok 1231 / compression_fail 248)
- 앞 구간에 말소리가 있다는 것도 확인했다. 음절변조 0.26~0.33으로,
  뒤 구간(0.40)보다 약할 뿐 무음이 아니다

## D17 — 놓친 구간의 글자는 버리지 않고 그 시간대로 되돌린다

D16에서 넘침 가드를 넣었는데 **잘못된 쪽을 버렸다.** 큐가 받은 텍스트의 앞부분을
남기고 뒷부분을 버렸다. 절단점 사상의 정의상 큐가 받는 텍스트는
`[앞 큐가 끝난 시각, 이 큐가 끝난 시각]` 동안 나온 말이다. 즉 **앞부분은 앞 공백에서
나온 말이고, 큐가 실제로 덮는 시간에 나온 말은 뒤쪽이다.** 정확히 거꾸로 했다.

그리고 버릴 일이 아니었다. 그 시간대에 사람이 한 말이고, 놓인 자리만 틀렸다.

`vlogsrt/gapfill.py`가 `mapping.rescue_orphans`를 대체한다. 차이는 하나다.
rescue_orphans는 **전체 골격을 다시 정렬**해서 고아 구간의 텍스트를 찾았는데,
환청 구간에서는 그 정렬 자체가 무너진다(같은 문장이 100번 반복되니 대응점이
아무데나 붙는다). gapfill은 정렬을 믿지 않는다. **시간축만 본다.**

- 큐 앞의 빈 시간에 걸러낸 세그먼트가 있으면 그것을 시각의 닻으로 쓴다.
  환청 구간이라도 **세그먼트 경계는 오디오를 따라간다.** 못 믿을 건 텍스트뿐이고,
  그 텍스트는 어차피 최종 SRT에 안 들어간다(불변 규칙 2)
- 닻이 없고 큐가 넘치기까지 하면 그때만 균등 분할한다
- `silent` 판정은 닻으로 쓰지 않는다. "그 시간에 발화가 없었다"는 판정이라
  거기로 글자를 옮기면 없는 말을 만들어내는 셈이다
- 텍스트는 시간에 비례해 나눈다. 큐는 **꼬리**를 갖는다
- 붙어 있는 큐(간격 < `min_duration`)는 한 묶음으로 배분한다. 따로 하면 뒤엣것이
  자리를 못 얻는다 — 실측에서 933자짜리 큐 하나가 그렇게 살아남았다

골격에서 온 큐의 start/end는 건드리지 않는다(불변 규칙 3). 새로 만든 큐만
`time_estimated`를 달고 나가고 신뢰도는 `orphan_conf_max`로 눌러 둔다.

같은 픽스처(프롬프트 오염된 최악의 입력)로 잰 결과:

| | 이전 (버리기) | 지금 (되돌리기) |
|---|---|---|
| 최대 큐 글자수 | 881자 | **96자** |
| 200자 넘는 큐 | 3개 | **0개** |
| 정본에서 빠진 어절 | 2개 | **0개** |
| 덮은 시간 | 41.6% | 45.8% |
| 0~600초 큐 | 4개 | **67개** |
| 3분대(150~250초) 큐 | 0개 | **8개** |
| 최대 공백 | 569초 | 348초 |

남은 공백은 whisper가 세그먼트조차 주지 않았거나 0.85초 미만짜리만 준 구간이다.
거기까지 채우려면 시각을 순전히 지어내야 해서, 하지 않는다.

## D18 — 되풀이 구간은 판정 단계에서 강등한다 (2026-08-17)

### 증상

새 녹화(프롬프트 없음, 저역 필터 적용)에서도 앞 3분·뒤 6분 자막이 통째로 비었다.
로그: `'오 오 오 …' 30~177초 · 5회`, `'음..' 4247~4598초 · 210회`,
`빈 큐 538개를 버렸다`.

### 원인 사슬

세그먼트를 가로지르는 되풀이는 압축률(세그먼트 안쪽만 봄)을 통과해 **verdict가
ok로 남는다.** ok라서 (1) 큐가 되어 시간축을 차지하고 (2) 정렬 기준 문자열에
들어가 절단점을 무너뜨린다. 결과: 되풀이 구간 큐들이 빈 텍스트를 받고, gapfill
시점엔 그 빈 큐들 때문에 공백이 없는 것처럼 보이고, 마지막 refine에서 빈 큐가
버려지며 그 시간대가 통째로 사라진다.

### 결정

1. **`loops.demote`** — 골격 생성(fetch_spine)의 마지막에, 되풀이 구간의 ok
   세그먼트를 `compression_fail`로 강등한다. 큐도 정렬 재료도 아니게 되고
   gapfill의 시각 닻으로만 남는다. `silent`는 건드리지 않는다(발화 없음 판정을
   닻으로 바꾸면 없는 말을 만든다). 생성이 끝난 골격은 여전히 불변이다(규칙 1).
2. **빈 큐는 gapfill이 지운다** — 글자가 없으니 잃는 것도 없는데 자리만 차지해
   그 시간대를 공백이 아닌 것처럼 보이게 하기 때문이다.
3. **창 조각내기(`_burst`)** — 닻 창이 길거나 글자가 넘치면 `max_duration` /
   `max_chars_per_cue` 기준으로 나눈다. 조각은 `min_duration`보다 짧아지지 않는다.
   (실측: 8초 창에 359자가 큐 1개로 얹혔다.)
4. **앞으로 흘리기(`_spill_forward`)** — 큐가 용량을 넘치면 꼬리를 **뒤따르는**
   걸러낸 세그먼트 시간대로 보낸다(D16의 "첫 큐 0.77초에 900자"가 이 모양이다).
   마지막 묶음은 넘치지 않아도 보낸다 — 절단점 사상이 남은 정본 전부를 마지막
   큐에 얹기 때문이다. 기존의 "마지막 큐 전용" 뒤 공백 처리를 일반화한 것이다.

### 실측 (프롬프트 오염 픽스처, D17 대비)

| | D17 | D18 |
|---|---|---|
| 빈 큐 | 538개 상당 | **2개** |
| 뒤 되풀이 구간(3941~4510초) | 큐 1~2개 | **큐 58개 · 1229자** |
| 4200초 이후 큐 | 거의 없음 | **51개** |
| 최대 큐 글자수 | 96자 | 122자 |

### 남은 한계

이 픽스처의 178~582초는 여전히 비어 있다. 프롬프트 오염이 582초 **이후**의
whisper 텍스트까지 망가뜨려(길이 0 세그먼트 37%) 정렬이 앞 구간 정본을 582초
이후 큐들에 얇게 발랐고, 어느 큐도 용량(× `overflow_factor`)을 안 넘겨 흘림이
발동하지 않는다. 새 녹화는 whisper에 프롬프트가 안 가므로 이 이중 붕괴가
재현되지 않아야 한다. 재현되면 그때 `overflow_factor`를 근거와 함께 재검토한다.

## D19 — 2모델 사상을 버리고 whisper 단독 + gpt 검증으로 전환한다

날짜: 2026-08-17

### 증상

사상(mapping) 계열의 실패가 반복됐다. 0.77초 큐에 900자(D16), 9분 큐 점프,
그리고 D17·D18의 보상 로직 연쇄 — 최근 커밋 5개가 전부 gpt 텍스트를 whisper
시각에 꿰매는 봉합의 땜질이었다. 사용자 체감은 "영상과 자막 싱크가 안 맞는다".

### 근거

- D13 계측이 전처리를 이미 무죄 방면했다: 청크 오프셋 오차 0.0초, 필터
  타임라인 오차 0.000초. 병소는 전처리가 아니라 **두 텍스트를 정렬하는 사상
  단계 그 자체**다.
- 한 모델(whisper-1)이 시각과 텍스트를 동시에 내면 사상이 소멸하고, 싱크는
  구조적으로 보장된다. 텍스트 품질 하락은 gpt를 **검증자**로 돌려 플래그로
  보완한다 — 출력은 손대지 않는다.

### 결정 (사용자 지시)

1. **동기화가 1순위 목표다.** SRT의 시각·텍스트 전부 whisper-1 유래.
2. **gpt-transcribe는 검증 전용.** `verify.py`(신규)는 순수 함수 — 큐를 만들지도
   고치지도 못하고, 검증 on/off에 SRT는 바이트 동일. 검증 실패는 SRT를 막지 못한다.
3. **사상 계열 삭제**: `mapping.py`, `gapfill.py` + 테스트 41개.
   복귀 경로는 git — 마지막 사상 커밋은 `564d0be`.
4. `baseline` 서브커맨드 삭제 (`run --stop-after output`이 같은 역할).
   `redo`는 spine→cues→refine 재정제 전용.
5. 음질 필터 체인 제거는 P6에서 별도 커밋 (D20으로 기록).
6. `TRACE_VERSION` 인상 — 옛 trace는 `redo`에서 명시적 오류.
